# 模块设计：技能封装（Skills Packaging & Routing）

> 对应规格：`doc/openspec/specs/skills/spec.md` ｜ 接口：`doc/03-interfaces/skills-interface.md`
> 定位：**L3 记忆 ↔ L1 插件 之间的结晶层**，把高频业务能力沉淀为可复用的标准化资产。

---

## 1. 模块定位

CORE 的核心创新是"记忆即光谱"：经验（L2 事实）→ 技能（L3）→ 插件（L1）是同一光谱的不同结晶度。

本模块负责 L3 技能这一段的**封装、版本化与路由**，是"结晶经济闭环"的上半场（下半场是 evolution 的溶解）。

---

## 2. 内部组成

```
SkillManager（L3）
├── SkillLibrary     原子技能库：技能注册表，按能力/领域索引
├── VersionManager   技能版本管理：迭代、灰度发布、A/B 测试
├── SkillRouter      技能路由：按任务类型自动匹配最合适技能
└── SkillIndex       技能目录索引：轻量化元数据，支持按需加载
```

---

## 3. 关键设计

### 3.1 原子技能库

- 技能 = 一组可复用的指令/流程/参数模板，封装为独立可调用单元（不依赖 prompt 现场重写）。
- 每个技能有：`skill_id`、描述、适用任务类型、前置条件、参数 schema、执行说明。
- 技能按领域分类（数据分析、文档生成、代码调试…），支持层级索引。
- **可落盘**（0050）：注册表可注入 `path` 落盘为单文件 JSON 并在启动恢复（缺省纯内存）；
  同族落盘面还有反馈统计、SOP 样本、灰度·A-B 状态——见 ADR-0053。
- **显式启用**（`0133`／ADR-0126／账本 E72）：`SkillLibrary.activate(skill_id)` 把 `draft` 迁
  `active`（CLI `skill activate <name>`）—— 此前市场下载恒落 draft 却**无路可用**（路由放行集
  只含 `active`/`gray`），是死胡同。启用**幂等**（已 active 为 no-op）、未知 id 抛 `KeyError`、
  注入追踪器时登记可逆效应；**不自动启用**、**不扩大路由放行集**。

### 3.2 技能版本管理

- 技能迭代采用世代版本（`v1 → v2 → …`），与插件世代语义一致。
- 支持**灰度发布**：新版本仅对部分任务生效，观察指标后再全量。
- 支持 **A/B 测试**：新旧版本并行，用 observability 指标量化对比，效果好才提升为 active。
- **闭环接线**（#8）：执行反馈不达标（样本 ≥ 3 且失败率 ≥ 0.5）→ 注入的改写器重写
  `instructions` 为新版本草稿并灰度（比例 0.3）→ 两版本样本齐备后 A/B 定夺：提升则落地新版本
  （版本号 + `instructions` 一并写回，登记可逆效应），退化则**只丢草稿、技能不动**。
  `SkillIterator` 是 `VersionManager` 三段能力的唯一生产调用者；灰度/A-B/稳定版状态可落盘
  （0050，组合根显式构造并注入，见 ADR-0053）。

### 3.3 技能路由机制

```
任务类型 ─► SkillRouter.match(task) ─► 匹配度排序 ─► 返回 Top-K 技能
                 │                          └─► 无匹配 → 回退通用 loop / 转人工
                 └─► 词法命中即返回（fast path）；词法全无命中时语义兜底（注入打分器时）
```

- 路由依据：**排序分 = 基础分（词法命中率 fast path / 语义兜底分）× 历史成功率因子**（0058）。
  因子取自 `#8` 的命中/结果反馈（`SkillFeedback`，按 `(skill_id, version)` 累计）：**无样本 = 1.0**
  （冷启动中性，不惩罚新技能），有样本 = `0.5 + 0.5 × 成功率`（下限 0.5，防「一次失败即永不入选」
  的正反馈）。组合根把该实例同时注入路由与迭代器（单一真源）。
- **加权只改排序、不改命中**：词法命中筛选与语义阈值判定的都是**基础分**，否则加权会静默改变
  「算不算命中」的口径。未注入反馈记录器时因子恒 1.0（行为与纯基础分一致）。
- 自动匹配，无需人工指定；匹配结果可被 loop 采纳或覆盖。
- 语义兜底只在**词法全无命中**时触发（避免把辅助决策成本抬到每个推理轮），打分器缺省不启用。
- 命中结果**真正进 prompt**（#8）：组合根把命中快照（`skill_hint`：id + 版本 + `instructions`
  节选 ≤ 400 字符）交给 planner 渲染为技能块；loop 只吃纯 dict（不 import skills）。

### 3.4 SOP 提炼（技能的产生入口）

技能库此前只有注册 / 路由 / 版本三段，**没有任何产生技能的路径**；`SopExtractor` 补上这一段
（接口见 `doc/03-interfaces/skills-interface.md` §6）：把**同一类任务的多次成功轨迹**聚合、
提炼为一条 `Skill` 入库（可逆）。**两个观察面**：

| 面 | 观察单位 | 接入点 | 命名空间 / 样本文件 |
|---|---|---|---|
| **单轮面** | 本轮的「工具（参数）→ 结果」行 | `DefaultLoop` 收尾钩子（每轮） | 无前缀 / `sop-samples.json` |
| **任务级面**（change `0197`／ADR-0187） | 任务目标 + 按 `plan.order` 聚合的子任务步序（**任务过程**） | 编排 `DoneFn`（成功 `DONE` 一次） | `task::` / `sop-task-samples.json` |

- **为什么要有任务级面**：长会话任务跨多轮 ⇒ 单轮面**每轮各自成样本、任务文本逐轮不同 ⇒ 归组键
  漂移 ⇒ 永不达阈**（`_SOP_MIN_SAMPLES=3`）⇒ 「长会话任务过程 → 技能资产」这条链**从未产出过东西**。
- **两面严格隔离**：步序语义不同（任务级 = 子任务**骨架**；单轮 = 工具调用**行**），混组会产出浑浊
  SOP ⇒ 样本文件、组键（前缀 `task::`）、`skill_id` 三者**全隔离**；隔离是**正确性**要求。
- **只吸收成功**：`DoneFn` 只在 `DONE` 时调用、`observe(ok=False)` 直接丢弃 ⇒ 失败轨迹不入 SOP
  （教训走 memory / evolution 通道）。
- **发布前过自动质量门（change `0198`／ADR-0188）**：非空提炼产物先过注入的 `SopGate`
  （**纯 callable**，实现由 `judgment` 以 **noul** 原语提供）——**未过** ⇒ 不入库 + **清空该组**
  + 留痕（**只报组键，绝不回显正文**）；**判定故障 / 缺答案** ⇒ **放行**（fail-open：新增的刹车
  不得把「一直正常发布」变成静默不发布）。缺省（未配置 JEV）⇒ 无门 ⇒ 发布路径**逐字不变**。
  门是**自动**判定 ⇒ 守红线「维度1 技能库/SOP **全自动**」（**不**引入人工确认）。

## 4. 结晶与溶解（与 evolution/memory 的闭环）

```
L2 事实 ──反复出现的成功模式──► L3 技能（SkillLibrary）
L3 技能 ──复用次数达阈值 + 过验证门──► 结晶为 L1 插件（evolution 结晶）
L1 插件 ──在留出集退化 / 失效──► 溶解回 L3 技能（evolution 溶解）
```

- 结晶阈值可配置（默认：复用 ≥ N 次且验证门通过）。
- 溶解时保留"教训"写回 L3，避免同类错误再结晶。

---

## 5. 错误处理

| 场景 | 行为 |
|---|---|
| 技能前置条件不满足 | 拒绝调用，返回 `PRECONDITION_FAILED` |
| 路由无匹配 | 回退通用 loop，记录未命中（供新技能沉淀）；记录 id 由**任务内容**+会话键确定性派生（`blake2b`）⇒ 跨进程不互相覆盖、同任务同会话幂等；`misses` 为有界诊断窗口（`_MISS_WINDOW = 64`）（change `0117`／ADR-0110） |
| A/B 中 B 显著退化 | 自动切回 A，B 标记 deprecated；**草稿版本**退化则只丢草稿（技能不被误标） |
| 技能 schema 非法 | 拒绝入库，返回 `INVALID_SKILL_SCHEMA` |
