# CORE-Harness 产品定义（Product Definition）

> 版本 v0.1 ｜ 状态 Draft ｜ 本文回答"**为什么做、为谁做、做什么、不做什么、怎么算成功**"。

---

## 1. 产品愿景（Vision）

构建一个**无特权核心、可组合、可观测、递归可进化**的通用智能体运行时：
开发者像拼乐高一样组合插件装配智能体，系统像生物进化一样，把重复经验**结晶**成技能与代码，
并在失败时**可逆**回退——让智能体**会记、会学、会进化，且永不失控**。

一句话：**CORE-Harness = 插件化的骨骼 + 光谱化的记忆 + 结晶化的进化。**

---

## 2. 背景与问题（Problem）

| 现状痛点 | 描述 |
|---|---|
| P1 智能体"失忆" | 多数 agent 每轮从零开始，经验不沉淀，token 成本线性膨胀 |
| P2 进化不可归因 | 端到端自进化改的是全局代码，缺陷无法定位到具体模块，回滚=推倒重来 |
| P3 框架固化 | 工具集写死在核心，加一个能力就要改核心、冒全局风险 |
| P4 记忆与代码割裂 | "会记"的系统不改代码，"会改"的系统不留记忆，两者不连通 |

CORE 通过**三源融合**（dsh 插件化基底 + ModularRSI 可归因进化 + GA 分层记忆结晶）同时解决上述四点。

---

## 3. 目标用户（Target Users）

| 用户画像 | 核心诉求 | 典型场景 |
|---|---|---|
| **智能体开发者** | 快速装配/替换能力，低耦合 | 拼装"代码执行 + 浏览器 + 记忆"智能体 |
| **AI 研究员** | 做可控、可归因的自进化实验 | 在留出评测集上验证进化是否泛化 |
| **自动化工程师** | 长期运行、经验可复用、故障可回滚 | 长任务中让 agent 自动沉淀 SOP |
| **平台/工具方** | 用 MCP 把自己的能力接入任意 agent | 提供 MCP server 暴露内部 API |

---

## 4. 价值主张（Value Proposition）

1. **可组合（Composable）**：一切皆插件，无特权核心；换 loop、换记忆后端、换模型适配器都只是换插件。
2. **可观测（Observable）**：所有副作用可逆、可追踪；任何状态可回放、可回滚。
3. **可进化（Evolvable）**：进化是模块级、可归因、过验证门的；坏进化可一键卸载，教训回写记忆。
4. **可记忆（Memorable）**：经验→技能→插件连续结晶，token 成本有上界，能力随时间单调（可逆）增长。

---

## 5. 范围（Scope / In-Scope）

**MVP（v0.1）必须包含：**

- **L0 基底**：插件注册表（registry）、可逆效应追踪、coeffect（环境注入）解析、热插拔（HMR）。
- **L1 原子工具**：至少 9 个可逆插件（code_run / file_read / file_write / file_patch / web_scan / web_execute_js / ask_user / memory 读写 / 进程控制）。
- **L2 分层记忆**：L0 元规则、L1 索引、L2 事实、L3 技能（SOP）、L4 归档，五层可读写可查询。
- **L3 智能体循环**：感知→推理→行动→写记忆的最小闭环，默认实现 ~100 行。
- **L4 进化引擎（骨架）**：诊断、提案、验证门、留出评测四个插件的**接口 + 最小实现**。
- **MCP 集成**：作为 MCP client 消费外部 MCP server 的 tools/resources/prompts。
- **宪章/安全**：人机确认门、爆炸半径控制、不可逆操作必问。

## 6. 非目标（Out-of-Scope，MVP 明确不做）

| 非目标 | 说明 | 何时再做 |
|---|---|---|
| 分布式/多进程调度 | 单进程可观测优先 | v0.3+ |
| 向量数据库内置 | 记忆后端可插拔，文件后端先行 | v0.4+ |
| 完整的多模型训练/微调 | 只做推理期自进化 | 远期 |
| GUI 编辑器 | 先 CLI + Markdown 规格 | v0.5+ |
| 跨语言运行时（TypeScript 等） | Python 3.11+ 优先 | 按需 |

## 7. 成功指标（Success Metrics）

| 编号 | 指标 | 目标值（v0.1 验收） | 衡量方式 |
|---|---|---|---|
| M1 | **结晶命中率** | L3 技能被复用 ≥ 3 次即提升为插件的比例 > 60% | 记忆/插件日志统计 |
| M2 | **进化可回滚** | 100% 进化变更可一键卸载恢复 | 验证门 + 世代化测试 |
| M3 | **归因精确度** | 诊断能定位缺陷到**单个插件**的准确率 > 80% | 留出缺陷注入实验 |
| M4 | **token 上界** | 长任务 token 增长随任务数呈**次线性**（记忆外置生效） | 基准任务序列测量（已落地：`tests/test_m4_token_growth.py`，change `0274`） |
| M5 | **组合成本** | 新增一个能力（新插件）改动核心文件数为 **0** | 代码审查 + CI 检查 |
| M6 | **留出泛化** | 进化后的系统在留出评测集上不退化（Δ ≥ 0） | held-out eval |

## 8. 关键术语表（Glossary，与全文档一致）

| 术语 | 定义 |
|---|---|
| **插件（Plugin）** | 系统的最小原子能力单元，含生命周期 + 可逆 effect + coeffect 声明 |
| **可逆效应（Reversible Effect）** | 带"撤销函数"的副作用，支持时间旅行回滚 |
| **Coeffect（共效应）** | 插件从环境**读入**的约束/依赖（权限、宪章、配置），与 effect 对偶 |
| **结晶（Crystallization）** | 经验→技能→插件 的连续提升过程；反向为溶解（Dissolution） |
| **世代（Generation）** | 一次过验证门的进化产物，不可变、版本化、可回滚 |
| **验证门（Validation Gate）** | 进化产物必须通过 review + 运行时测试才可发布 |
| **留出评测（Held-out Eval）** | 与训练/进化过程不相交的评测集，用于验证泛化、防止过拟合 |
| **无特权核心（No Privileged Core）** | loop、模型、记忆、进化引擎均为插件，L0 基底只提供组合代数 |
