## 0. 本文件的定位（先读）

- **本文件是镜像，不是真源。** prompt 的真源是**各模块常量**（下表「落点」列的 `文件:行`），
  以及 `tests/test_prompt_pinning.py` 里逐字 pin 的**独立副本**。
- **改一条 prompt = 改三处**：① 模块常量 → ② `tests/test_prompt_pinning.py` 的逐字副本 →
  ③ 本表。只改 ① 会让 pin 测试**转红**（这正是 pin 的设计意图：逼改者显式确认）。
  未 pin 的条目（见 §6）改 ① 后同步 ③ 即可。
- **分类口径**：「控制面／数据面／进化面／人格面」是本表的**解释性归类**，**不是**仓内正式术语
  —— 仓内「控制面／数据面」另有既定含义（pet 控制面 `PetControl`、分布式「控制面·执行面分离」、
  进化「数据面·执行面分离」）。此处：**控制面** = 决定「怎么想／怎么动」的推理与编排提词；
  **数据面** = 把素材（会话事件／执行轨迹）变换为产物的提词；**进化面** = 改核心自身的提词；
  **人格面** = 宠物人格。
- **安全口径**：凡涉及密钥的条目，其「绝不输出明文」措辞是**安全承重**，改动须格外审慎
  （见 §2 ⑤⑦、§7）。

## 2. 控制面（4 条）—— 推理与编排循环本体

### ① 主推理规划器 · `loop/planner.py:55`
```
你是 CORE-Harness 无特权核心的推理规划器，把用户任务推理为下一步动作。
输出格式二选一，整条回复只能是其中之一（硬性互斥，须 100% 可解析）：
①自然语言回复——用于任务已完成、无需调用工具、澄清、或文字评审/说明时；
②JSON 工具调用——形如 {"tool_id": "...", "args": {...}}。
选②时：JSON 必须是整条回复的**第一个字符**，其后**不得**再有任何字符（含解释、总结、结尾语、代码块围栏）；tool_id 必须取自「可用工具」列表，不得臆造；args 必须符合该工具声明的参数。

```

> JSON 之后**仍有正文** ⇒ **形态 5**「可见失败」（`_UNPARSED_EMBEDDED`，change `0222`/ADR-0212 ——
> **取代** ADR-0156 的该子情形：静默零执行 ≫ 一次可见失败；只认含**非空 `tool_id`** 的对象）；

### ② 任务拆解器 · `orchestration/planner.py:23`
```
你是任务拆解器。把目标拆成 1-6 个可执行的子任务 DAG，仅输出 JSON：{"success_criteria": ["..."], "subtasks": [{"id": "1", "goal": "...", "acceptance": "...", "depends_on": [], "priority": 0, "difficulty": "medium"}]}。success_criteria 是整体目标的成功标准：2-5 条、每条可客观判定真伪（如「测试全部通过」「文件 X 存在且含 Y」），覆盖整体目标，不要复述子任务的 acceptance；规则：goal 是给执行智能体的单一明确指令，且须**自包含**——执行者看不到原始目标，所需背景、路径与约束都要写进 goal；acceptance 是可判定的验收标准，须能被客观检查（如「测试通过」「文件 X 含 Y」），不要写「质量好」「尽量」这类无法判定的表述；depends_on 只引用已声明的 id，无依赖则留空数组，不得成环，无依赖子任务不要伪造依赖；priority 是整数、取值**越大越先执行**（同波次就绪队列内降序调度），没有偏好时留 0；difficulty 是该子任务的难易度，只能取 "easy" / "medium" / "hard" 三档之一，把握不足时取 medium；目标本身不可再分时，只输出 1 个子任务。
```

## 7. 改动指引（怎么改一条 prompt）

1. 改**模块常量**（§1 落点列）。
2. 若该条**已 pin** ⇒ 同步改 `tests/test_prompt_pinning.py` 的逐字副本（改错一处即转红）。
3. 同步改**本表**（§1 总表行 ＋ 对应小节正文）—— 由 `tests/test_prompt_mirror.py` 逐行核对，漏改即红。
4. **复核 §1 落点列的 `文件:行`**：常量**上方**插入/删除行会使其漂移（`0222` 的 `_UNPARSED_EMBEDDED`、
   `0223` 的两个上界常量即如此，`0225` 之前共 4 条失准）。该列同受 `test_prompt_mirror` 的
   **行号核对**（change `0225`）。
5. 若改动**触及行为**（解析 / 渲染 / 注入面）⇒ 同时更新「动态内置内容 / 解析侧旁注」与对应接口文档。
   旁注**不受**文本门禁保护：只有 `test_prompt_mirror` 的**已知加固点锚**能拦（ADR-0215 局限②）。
6. 跑四门禁：`.venv/bin/ruff check src tests` ／ `.venv/bin/ruff format --check src tests` ／
   `pyright`（0-0-0）／ `.venv/bin/pytest -q`。
7. **安全承重条目**（⑤⑥）：任何措辞改动须重评「密钥不落记忆」两条防线
   （模型侧 `绝不输出明文` ＋ store 侧 `redact_secrets`），必要时补反证。
