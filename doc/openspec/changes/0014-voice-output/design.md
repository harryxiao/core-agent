# Design

## Context

语音输出与语音输入共同构成完整的语音交互闭环。输入侧（多模态输入：语音转写）已声明，本 design 补齐输出侧：将内核流式文本分片经 TTS 合成实时播报，并支持 barge-in 打断。全双工（边听边播）是语音对话的自然范式，三模（CLI/Web/Desktop）需行为一致。

## Decisions

- **流式播报**：内核产生分片文本即增量送入 TTS 合成并连续播报，不等待整段回复，降低首字延迟。
- **barge-in 打断**：用户开口说话或按下打断键立即停止当前播报并转入语音输入；被打断文本不丢失，保留在会话记录。
- **上下文统一**：语音与文本共享同一会话记录（不维护独立语音上下文），必要时保留原始音频引用。
- **三模一致**：CLI / Web / Desktop 复用同一语音输出能力与交互语义，仅呈现层适配。

## Risks / Trade-offs

- **打断误触发**：环境噪音可能误判为用户开口，需 VAD 阈值与手动打断键兜底。
- **流式合成卡顿**：TTS 分片合成延迟可能导致播报断续，需缓冲与排队策略。
- **音频引用存储**：保留原始音频引用增加存储，需权衡是否仅保留文本与可选的短音频。

## Open Questions

- TTS 引擎选型（本地引擎 vs 云 TTS API vs 混合）留待实现阶段确定。
- 是否支持语音速率/音色等个性化播报设置，首期是否内置。
