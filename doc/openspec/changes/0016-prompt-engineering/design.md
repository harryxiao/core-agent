# Design

## Context

change 0015 已确立两级 Core.md 文件格式（双语义分区）与加载行为，但编写侧缺失指导：宪法条目如何写才能被 constitution:v1 coeffect 可靠执行、人格如何写才能落 L0 记忆层且不稀释元策略、项目信息如何写才能不重复全局规则、篇幅如何控制。本 design 补齐题词规范（编写技法）与题词模板（骨架），与 0015 的运行时行为正交：0015 管「文件怎么解析/加载」，本 change 管「文件怎么写」。

## Decisions

- **题词规范（R6）**：三分区各自编写规则——宪法与全局规则用命令式可判定句式（每条「必须/禁止」、可判定真伪、不承载操作细节）；人格用结构化描述（身份/工作风格/沟通风格/决策偏好/边界意识）；项目信息仅写项目特有信息且不重复全局规则；篇幅受控（≤50 行，细节下沉 L2/L3）。
- **题词模板（R7）**：两级骨架——全局级含「宪法与全局规则」「人格」两分区，项目级含「项目信息」一区；模板附分区注入说明注释，注明各分区内容落向的运行时通道（constitution:v1 / L0 / ContextEngine）。
- **authoring 非运行时**：本 change 只声明编写规范与模板，不改任何运行时解析/加载行为，故不动接口文档。

## Risks / Trade-offs

- **规范与运行时脱节**：题词规范要求「可判定」，但 0015 的分区标记语法留待实现阶段确定，需在实现阶段确保解析器能校验「必须/禁止」句式。
- **篇幅约束 vs 灵活性**：≤50 行是建议而非硬限，需避免为凑行数牺牲宪法完整性。

## Open Questions

- 是否提供 linter/校验工具自动检查「必须/禁止」句式（留待实现阶段）。
- 题词模板的注释语法（markdown 注释 / 显式提示行）与 0015 分区标记语法一并确定。
