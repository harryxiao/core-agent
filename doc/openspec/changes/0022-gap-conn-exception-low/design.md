# Design

## Context

全局架构审查（2026-09-22）发现：低优先级七模块在健壮性与连接管理细节上存在轻微缺口。本 change 均为对既有 Requirement 追加 Scenario，不新建 Requirement，requirements.md 无改动。

## Decisions

- **mcp 心跳保活 + 连接关闭与资源释放**：心跳由 Requirement 文字提及落为独立保活 Scenario；连接关闭时释放会话与连接资源，避免连接泄漏
- **plugin-registry 并发热插拔原子性 + 注册超时**：插件并发热插拔保持原子性；注册 / 校验超时兜底，避免挂起阻塞
- **loop 单轮回滚**：单轮失败按该轮回滚语义回退本轮副作用，不污染后续轮次
- **composition bundle 循环依赖检测 + patch.yml 覆盖冲突兜底**：bundle 分发前检测循环依赖并拒绝；用户覆盖与默认配置冲突时按规则兜底
- **context 重建失败二阶兜底**：信息地图重建失败后降级全文检索兜底，保证检索可用
- **permission 沙箱销毁与资源回收**：沙箱不可用 / 任务结束后销毁沙箱并回收资源，避免泄漏
- **evolution 并发评测资源上限**：多提案并发评测时限制并发数与资源占用，避免打爆资源
- **spec 扩展非新 cap**：七模块均归属既有 capability，不新建 capability

## Risks / Trade-offs

- 心跳间隔与超时判定阈值留待编码阶段确定
- 覆盖冲突兜底的具体优先级规则留待实现阶段确定
- 二阶兜底降级全文检索可能引入检索延迟，需权衡可用性与延迟

## Open Questions

- 并发热插拔的锁粒度与回滚策略留待编码阶段确定
- 并发评测资源上限的具体数值留待实现阶段确定
