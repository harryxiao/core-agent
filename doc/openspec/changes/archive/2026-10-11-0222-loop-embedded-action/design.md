# Design 0222 — 夹带的动作 JSON 归一为可见失败

## D1 判据 = 「已闭合 + 非空 tool_id + 其后仍有正文」（形态 5）

**实现**：`_embedded_action_payload(text)` 逐 `{` 起 `json.JSONDecoder().raw_decode` 试解析；命中
**闭合的 dict 对象**、`tool_id` 非空、且 `text[end:].strip()` 非空（其后仍有正文）⇒ True。

**与既有判据的关系（互斥，不重叠）**：
- 形态 3 `_trailing_json_object`：对象**收在文末** ⇒ 工具动作（逐字不变）。
- 形态 4 `_unclosed_action_payload`：结构**未闭合** ⇒ 失败（逐字不变；其判据明写「闭合对象一律不命中」）。
- 形态 5（新）：对象**已闭合**但**不在文末**（其后有正文）⇒ 失败。

三者按 `_parse` 次序判定：先形态 3（命中即返工具动作），再形态 4（未闭合），再形态 5（闭合但夹带），
最后兜底回复。**次序即语义**：形态 3 优先保证既有尾部动作路径零回归。

**不选**「执行夹带的动作 JSON」：那需要启发式判断「这 JSON 是模型真要执行、还是解释协议时引用的
示例」—— 规格明写「只认严格形态、不做启发式猜测」。归一到**可见失败**是严格形态下的保守选择。

## D2 **代价与取代**：静默丢失 ≫ 一次可见失败

**旧语义**（ADR-0156「只认尾部、宁漏勿误」）：正文中间夹带动作 JSON ⇒ 整段按回复，避免把「解释
协议时引用的 JSON 示例」误当执行。**动机合理，但**：当模型确实**发出**了完整动作协议、只是**又追加
了正文**时，旧语义把它变成**静默零执行 + 记成功 + JSON 进转录与记忆** —— 动作丢失、无信号、污染持久面。

**新语义**：闭合的**动作** JSON 夹带 ⇒ **可见失败**（`LLM_PLAN_PARSE_FAILED`，`failed=true`）。代价是
偶发误伤「解释协议、在正文里引用一个含 `tool_id` 的 JSON 示例」的回复（→ 该轮以解析失败收尾、用户
可重发），收益是**消灭静默零执行**。**二者不对称**：静默丢失不可观测且污染记忆；可见失败可观测、
可恢复、不进持久面。

**承接方式**：以 **ADR-0212 取代** ADR-0156 在该子情形的语义；ADR-0156 作为历史记录**不改写**
（沿 `0219`/`0221` 的「ADR 不可改写、新 ADR 承接」惯例）。旧测试 `test_action_json_mid_text_stays_reply`
与本语义冲突 ⇒ 改写为新语义断言。

## D3 误伤面收窄：只认**含非空 `tool_id`** 的对象

**不选**「任何中间夹带的 JSON 都失败」：解释/示例常引用**配置类** JSON（无 `tool_id`），把它们也判失败
是无谓误伤。判据要求 `tool_id` 非空 ⇒ **无** `tool_id` 的夹带对象仍按回复（规格 Scenario 明写）。

- **规格**：`loop` **MODIFIED**「推理动作解析与失败可见」（四种→五种形态、改写中间夹带句、
  MODIFIED 1 Scenario、ADDED 1 Scenario；**既有其余 7 Scenario 逐字保留**）⇒ canonical loop
  **6 → 6** req（无新增 Requirement）／ **81 → 82（+1）** scen。
- **反证（实测）**：摘掉 `_parse` 里的形态 5 分支 ⇒ `test_loop_output_protocol` **3 failed, 17 passed**；
  复原 ⇒ md5 相同、20 passed。
- **局限**：① 正文中**引用含 `tool_id` 的动作 JSON 示例**的解释型回复会被判失败（语义取代的固有代价，
  ADR-0212 已记）；② **流式泄漏未修**（PA-01 现象②，单独立项）；③ 判据对**多个**动作对象取「任一命中
  即失败」，不区分哪个是「真动作」。
