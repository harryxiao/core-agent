# TUI 代码块背景：可辨识（不透明 + 与主背景明显明度差）

## Why

- **用户实测（2026-10-07，change 0157 后续）**：TUI 里代码块「颜色没有变化，和主框颜色没差异，无法识别」。
- **根因（实证）**：Textual `MarkdownFence` 的默认样式是 `background: black 10%`（半透明黑）。
  本仓 TUI 为**深色**主题（`core`，`dark=True`），主背景 `#121212` ⇒ 叠加后合成为 `#101010`，
  与主背景**对比度 ≈ 1.02**，肉眼无从分辨。`color: rgb(210,210,210)` 只管字色、不产生**块的边界**。
  ⇒ 「围栏渲染为代码块」在**语法层**成立（E98 已保证走 Markdown 渲染），但在**视觉层**不成立 ——
  等同没渲染。
- **规格缺口**：`ui` spec「CLI 友好交互」只要求「围栏渲染为代码块」，**未**约束代码块与正文**可辨识**。
  该缺口正是本缺陷得以长期存在的原因（渲染对了但看不见，无 SHALL 兜底）。

## What Changes

- `src/core/ui/repl.py`：`ReplApp.CSS` 新增 `MarkdownFence` 规则 —— 背景改 `$surface-lighten-3`
  （本主题解析为中性灰 `#4F4F4F`，与 `#121212` 对比度 ≈ 2.3），**不透明**、一眼可辨；
  语法高亮 token 色（`$text-*` 系）仍为亮色 ⇒ 在**深灰**底上保持可读（这是**不**取「浅灰底 + 暗字」的
  原因：token 色由主题变量解析为亮色、压不到暗字，浅底会**吃掉**高亮）。
- `doc/openspec/specs/ui/spec.md`：「CLI 友好交互」**MODIFIED** —— 补「代码块 SHALL 与正文可辨识
  （背景不透明 + WCAG 相对亮度比 ≥ 2.0）」+ 1 Scenario。
- `doc/01-architecture/adr.md`：**ADR-0150** ＋ 变更追踪行。
- `doc/03-interfaces/ui-interface.md` §2：补代码块可辨识口径。
- `doc/04-testing/test-cases.md`：新增 `## 73.`（TC-CODEBG）。
- `coding-plan/known-risk.md` §1：E98 行补「后续 0158 收敛视觉层」；§3 加 ADR-0150 局限行。

## Non-goals（明确不做）

- **不做**「浅灰底 + 深色代码字」：token 色由主题变量（`$text-primary` 等）解析为**亮**色，
  浅底会把语法高亮**吃掉**（暗字只对未分词文本生效）。若要浅底须先改主题的 `$text-*` 变量面，
  波及全部用 `$text-*` 的控件 —— 另议。
- **不改**主题、不改其它控件样式、不改 Markdown 表格样式。
- **不动**渲染路径（0157 已把两条入口统一为 Markdown）；本 change **纯样式**。
- **不引**三方库。

## 风险

- **风险①：深灰底在**某些**操作者眼里仍偏暗**（「浅灰」的期望）。⇒ 颜色集中在一处 CSS 规则，
  一行可调（`$surface-lighten-3` → 更亮 token 或显式色值）；本 change 取「可辨识 + 不牺牲高亮」的
  最大公约数。
- **风险②：对比度门禁按 `$background` 计算** ⇒ 若主题背景色改暗/改亮，阈值可能需重估（测试会先红）。
