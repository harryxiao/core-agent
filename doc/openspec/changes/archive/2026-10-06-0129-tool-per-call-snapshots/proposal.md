# 提案 — 写类工具按次快照（回滚不再恢复错文件）（change 0129 / phase-34 E64）

## 背景

`coding-plan/phase-34.md`（全系统架构走查缺陷账本）登记的 **E64**（**高**，与 E63 并列影响面最大）：
`file_write` / `file_patch` 在**工具级**建**一个** `snap`，每次调用覆写 ⇒ 同一工具多次写入后回滚
**恢复错文件**。

| # | 一手事实（2026-10-06 复核，行号已核实） | 后果 |
|---|---|---|
| 1 | `tools/builtin.py:105-118`（write）与 `:136-147`（patch）在**闭包外**声明 `snap: dict`，handler 每次调用 `snap["path"] / snap["before"] = ...` **覆写同一份** | 快照**只留最后一次** |
| 2 | `undo()`（`:117-118` / `:146-147`）读**同一共享 `snap`** 交 `_restore`（`:282-292`） | 两次调用记录的两条 Effect **共用同一个 `undo` 闭包对象** ⇒ 逆序撤销两次都在还原**最后一次**的快照 |
| 3 | `runtime.py:397` 五个内置工具**只构造一次、跨 loop 复用**；`provider.py:137-148` 每次成功调用都 `record(Effect(undo=tool.undo, ...))` | 缺陷**生产可达**：同一会话内两次写不同文件即触发 |
| 4 | 规格 `tool-use/spec.md:50-53`「时间旅行回滚」已 SHALL「沿历史逆序执行各写类工具的撤销函数，**状态恢复到检查点**」 | 现状**违反**该 Scenario（回滚到检查点恢复不了） |
| 5 | 规格未写「每次调用各持独立快照」这一**构成要件** | ⇒ 按本仓 SDD 惯例**规格先行**（MODIFIED，非 `skip_specs`） |

**窗口（可达）**：任何「同一工具实例写两次」的会话。例：写 A（A 原存在）→ 写 B（B 原不存在），
回滚 ⇒ 两次 undo 都作用于 B 的路径：B 被删除两次、**A 停留在写入后的内容**（未还原）。
**跨 trace 更糟**：`t1` 写 A、`t2` 写 B 后只回滚 `t1` ⇒ 会去还原 **B**（触及本不该动的 trace）。

## 变更目标

`tool-use/spec.md` **MODIFIED「撤销与时间旅行回滚」**（正文补按次快照口径 + 2 个新 Scenario）：

1. **撤销函数按次生成** —— 每次成功执行后取得一份绑定**该次**写入前快照的撤销闭包；
   同一工具实例跨多次调用的快照 SHALL **各持独立**（按 trace 的 LIFO 序），SHALL NOT 被后续调用覆写。
2. **撤销第 N 次恢复该次内容**；并钉住 **跨 trace 不串**（只回滚 `t1` 时 `t2` 的副作用逐字不变）。

## Non-goals

- **不改 `_restore` 语义与签名**（`:282-292` 逐字不变）：仍「原不存在则删除、否则写回原内容」。
- **不改 `EffectTracker` 的清账/幂等语义**（change `0128` 已落地）——本 change 只让**每次调用**交出
  **各自的**撤销闭包，回滚侧逐字不动。
- **不改确认门 / coeffect / 超时 / schema 校验**等调用管道。
- **不引入「撤销栈持久化」**：快照仍在进程内（跨进程时间旅行由 `durability` 的检查点承担）。
- **不覆盖并发同工具调用**：file_write / file_patch 的 handler 为**同步**，`provider._call` 与其后的
  取闭包之间**无 await**（`:164-168`）⇒ 「压栈 → 取闭包」在同一事件循环步内完成，不存在交错窗口。

## 判据与取舍

**把 `Tool.undo` 定为「工厂」而非固定闭包。** 根因是「一条 Effect = 一个 undo 闭包」，而固定闭包
**读的是共享状态** ⇒ 后写覆写先写。可选修法有三：① 每次调用压一份快照、`undo()` 从栈弹出 ——
**跨 trace 仍错**（弹出的是栈顶，未必是本 trace 那次）；② 让 `EffectTracker` 按 trace 分组调用 —— 但
`undo()` 无参、无法自辨身份；③ **每次调用生成一份绑定自身快照的闭包**（本 change 取此）。
判据②③的差别在于「谁持有身份」：让**闭包自带**身份（捕获自己的快照）比让调用方**推断**身份更稳。

**代价**：`Tool.undo` 的类型由 `Callable[[], None]` 变为 `Callable[[], Callable[[], None]]`（空栈时
返回 no-op 闭包）。全仓只有 `builtin.py` 两处与 `provider.py` 两处触及（`register` 的
「有闭包却未声明写 coeffect」告警判据只是**存在性**判断，语义不变）。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 契约变更波及 `Tool` 的其它使用者 | 全仓 `undo=` 仅 `builtin.py:129/:158`（实现）与 `tests/test_tool_use.py:281`（告警桩）；无其它消费者 |
| 快照泄漏（handler 成功后未取闭包） | 压栈**在写入成功之后**；取闭包紧随 `_call` 返回，中间无 await |
| 既有「单次写 + 回滚」行为变化 | 逐字不变：单次调用时栈深为 1，弹出即该次快照（既有 `test_reversible_write_rollback` 回归守门） |

## 兼容性

- `ToolDef`（模型可见契约）**零变更**；工具 schema / 描述 / coeffect 均不动。
- `ToolResult` / `Effect` / `RollbackReport` **零变更**。
- 单次调用的回滚（此前唯一正确的路径）**行为逐字不变**；本 change 只让**多次调用**从「恢复错文件」
  变为「逐次各归各位」。
