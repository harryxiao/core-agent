# Design — 退化 JSON 的转义与内引号修复（change 0321）

## 1. 证据

| # | 事实 | 来源 |
|---|---|---|
| E1 | 事故原始产出结构完整、仅字面量写坏 | trace `a36c6cff…` `loop_finished.raw_output`（294 字符） |
| E2 | `_parse` 对 `{` 开头且 `json.loads` 失败：先 `_recover_truncated_tool_json`，再 `_first_brace_reply` 失败 | `planner.py:879-889` |
| E3 | 截断恢复只补 `}`、不补引号，且要求 `_leading_object` 为 `None`；本形态不命中 | `planner.py:248-273` |
| E4 | `_first_brace_reply` 对「未闭合」「夹带」均不命中的形态给通用文案 | `planner.py:915-928` |
| E5 | `loop.parse_retry` 缺省关，事故进程未开启 ⇒ 无回喂重试 | spec `loop`「推理动作解析与失败可见」 |
| E6 | 修复原型在事故原文上可解码，且 `script` 文本逐字保留 `\|` 与内引号 | 本轮离线复现 |

## 2. 决策

### D1 确定性修复，而不是只靠 `parse_retry`

回喂重试要多一次模型调用，且不保证第二次不再写坏；本形态的意图完全确定（命令文本就是原文），
修复零调用、可复现。`parse_retry` 仍保留为其他解析失败形态的兜底，二者不互斥。

### D2 判据：字符串感知的单遍扫描

- **非法转义**：`\` 后随字符不属于 `" \ / b f n r t u` ⇒ 输出 `\\`，原字符留给下一轮处理。
  合法转义（含 `\u`）原样保留，由 `json.loads` 继续校验十六进制。
- **内引号**：字符串内的 `"` 向后跳过空白，若已到文末或下一个字符属于 `, : } ]`，视为闭合；
  否则视为内容中的字面引号，补 `\"`。
- 合法 JSON 不会命中本判据（合法字符串内不存在裸露的 `"`），故对既有输入零影响。

### D3 采纳门槛与结构不补全

- 扫描结束时若仍**在字符串内**或**括号深度不为 0** ⇒ 放弃（未闭合 / 截断形态保持既有失败）。
- 修复文本必须 `json.loads` 成 **dict**，且 `tool_id` 非空字符串或 `reply` 非 `None`；否则放弃。
- **不**补括号、**不**补缺失引号、**不**删除任何已有字符 —— 只插入转义反斜杠。

### D4 顺序与重试关系

修复放在 `_recover_truncated_tool_json` 之后、失败动作之前。修复成功 ⇒ `_from_dict` 走既有
工具 / 终止语义，本轮不进入失败态，自然也不会触发 `parse_retry`。

## 3. 规格映射

`loop`「推理动作解析与失败可见」MODIFIED：新增一段修复规则，并追加三条 Scenario：

1. 未转义内引号 + 非法转义 ⇒ 恢复为工具动作，参数文本逐字保留；
2. 未闭合 / 截断形态不享受修复 ⇒ 维持失败态与有界 `raw_output`；
3. 修复后非动作对象（无 `tool_id` / `reply`）不采纳 ⇒ 维持可见失败。

## 4. 测试

`tests/test_degenerate_json_repair.py`：

| 用例 | 断言 |
|---|---|
| 事故原文复刻 | `tool_id == "tools.code_run"`、`script` 含 `grep -i "memory\|write\|deactiv"`、`failed is False` |
| 未闭合 + 非法转义 | `failed is True`、`reply` 以 `LLM_PLAN_PARSE_FAILED` 开头 |
| 修复后无动作字段 | `failed is True`、通用文案「无法解析模型输出为动作」 |
| 合法 JSON 含转义引号 / 反斜杠 | 解码值逐字不变（既有合法路径零影响） |

## 5. 反证

1. 删除 `_parse` 中的修复调用 ⇒ 事故原文用例红（恢复成失败）；
2. 关闭内引号修复（只修转义）⇒ 事故用例红（`json.loads` 仍失败）；
3. 去掉采纳门槛 ⇒ 「修复后无动作字段」用例红（变成「对象缺 tool_id/reply」而非通用文案）。

## 6. 局限

- 只覆盖**结构完整**的对象；未闭合 / 截断仍按既有失败语义（不猜缺失内容）。
- 引号闭合判据是启发式：若模型把闭合引号后误跟了正文单词（本身已是非法 JSON），会被当作
  内容引号；这是本形态下唯一可行且可测的方向，代价是该类写坏仍可能恢复成错误参数。
- 不校验工具参数语义；`INVALID_ARGS` 仍由工具链 Gate 承担，与本修复正交。
- 不改变 `parse_retry` 缺省关的策略，也不处理流式超时。
