# Proposal 0200 — 压缩轴口径裁决（轮 / 步两轴不可互换）

## 为什么

系统内**并存两个时间轴**，且规格**已分别如实记录**：

- **步轴**（轮内）：`上下文自动压实` 明写触发判据是「本轮**工具步数**达到 `loop.compact_steps`」，
  且明写「**非**对话轮数」（`context/spec.md` 压实触发段）。
- **轮轴**（跨轮）：`三层窗口比例分配` 明写分层以 `loop.history_turns` 为总量、切分单位是转录
  会话行。

但**两者的关系从未被裁决**，也没有任何文书禁止把它们**混算**。这个空缺有**实测前科**：change
`0182` / ADR-0173 就是一次「`rounds` → `steps`」的诚实化订正 —— 此前把**轮内步数**误读作
**对话轮数**，导致压实触发的语义被写错。而 `loop.compact_steps` 缺省 `6` 恰好落在外来蓝图
「Tier 2 自第 6 轮开始」的字面区间上（外部蓝图 `memory-4-layer-architecture.md` §4.1 的
`0-5 / 6-20 / 21+`），**极易再次被读成轮轴边界**。

本 change 是**文书化裁决 + 守护**：把「两轴各管什么、不可互换、蓝图字面边界不采纳」写成
**规格要求**，并以**守护测试**钉住。**零 `src/` 改动、零行为改动**。

## 做什么

- `context` 规格 **ADDED** 一条新要求「压缩轴口径（轮 / 步两轴不可互换）」+ 4 Scenario
  （步轴单独触发 / 阈值下不触发 / 步计数每轮归零 ⇒ 轮不可表达 / 分层边界随轮等比缩放）。
  既有 `三层窗口比例分配` 与 `上下文自动压实` **逐字不动**（不改既有阈值与配比）。
- ADR-0190：裁决正文 + 与外部蓝图的对照表 + **明确不采纳**的项。
- `tests/test_axis_units.py`：2 条守护测试（步轴 / 轮轴各一条），把要求里的每条 SHALL
  变成可执行断言。
- `doc/04-testing/test-cases.md` §113；`coding-plan/known-risk.md` §3 登记本 ADR 行。

## 不改什么

- **零 `src/` 改动**（`git diff --stat src/` 为空）—— 不新增配置键、不改任何阈值或配比。
- **不采纳**外部蓝图的字面 tier 边界 `0-5 / 6-20 / 21+`：它与既有**比率相对**方案
  （短 0.5 / 中 0.3 随 `history_turns` 缩放）会构成**第二套冲突边界**，而
  `三层窗口比例分配` 明禁在**配额分配面**新增配置键。
- 不重构 `plan_window` / `Compactor`（只**断言**其既有语义）。

## 规格影响

`context` **ADDED** 一条要求（4 Scenario）。既有 6 条 Requirement、既有 Scenario **全部逐字保留**
（本 change 不做 MODIFIED）。

## 风险

- **「文档不是契约」**：裁决类要求若不绑定断言，会退化成说明文。⇒ 本要求每条 SHALL 均由
  `tests/test_axis_units.py` 断言；ADR 明写「守护测试是**执行面**、Scenario 是**耐久锚**」。
- **误伤既有阈值**：本 change 只**读**既有常量（`_STEP_THRESHOLD`、`_SHORT_SHARE`）作断言，
  不引用其具体数值做分支 ⇒ 常量若被合法调整，守护测试的**语义**（步轴/轮轴分工）仍成立或
  显式转红，不会静默失真。
