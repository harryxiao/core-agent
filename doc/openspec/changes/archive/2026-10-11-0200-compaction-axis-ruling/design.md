# Design 0200 — 压缩轴口径裁决

## 裁决（一句话）

**两个轴各管一件事，不可互换**：步轴（`ctx.rounds`，每用户轮归零）管**轮内**压实触发；
轮轴（`history_turns`）管**跨轮**历史分层。`loop.compact_steps = 6` **只**是步轴阈值，
**不是**「第 6 轮开始压缩」。

## 两轴对照

| | 步轴（轮内） | 轮轴（跨轮） |
|---|---|---|
| 计量 | `LoopContext.rounds`（工具动作步数） | 转录**用户角色行**（对话轮） |
| 起点 / 归零 | **每用户轮**新建 `LoopContext` ⇒ 自 `0` 起算 | 会话全程累计 |
| 唯一旋钮 | `loop.compact_steps`（缺省 `6`） | `loop.history_turns`（缺省 `20`） |
| 消费者 | `Compactor.should_compact(steps, token_used, budget)` | `plan_window(turns, budget, tiered=)` |
| 规格落点 | `上下文自动压实`（触发判据段） | `三层窗口比例分配` |

## 与外部蓝图的对照（`memory-4-layer-architecture.md` §4.1）

| 蓝图 | 蓝图口径 | 本系统对应 | 裁决 |
|---|---|---|---|
| Tier 1 绝对保真区 | 最近 0–5 **轮** | 短层（原文逐字） | **映射到轮轴**：短层轮数 = 总量 × 0.5，**不用**字面 `5` |
| Tier 2 微压缩区 | 6–20 **轮** | 中层（模型摘要） | **映射到轮轴**：中层轮数 = 总量 × 0.3，**不用**字面 `6`/`20` |
| Tier 3 归档淘汰区 | 21+ **轮** | 长层（会话整体摘要） | **映射到轮轴**：长层覆盖更早全部内容（无轮数配额） |
| （蓝图未提） | — | **步轴**（轮内压实触发） | **保留**：蓝图没有的、更细的轮内机制 |

⇒ 蓝图的三个 Tier 边界**语义上落在轮轴**，本系统的三层滑窗已一一对应；`compact_steps` 是蓝图
**没有**的轮内机制，**不得**被塞进 Tier 边界。

## 为什么不采纳蓝图的字面边界

1. **会造出第二套冲突边界**：现有分层是**比率相对**的（短 0.5 / 中 0.3 随 `history_turns` 缩放）——
   `history_turns=40` 时短层是 `20` 轮，字面 `0-5` 与它无法并存。
2. **规格明禁**：`三层窗口比例分配` 要求份额为**模块常量、不新增配置键**，字面边界会引入一组
   新旋钮。
3. **蓝图自己也留了「可配置」**（Tier 2「6–20 轮（可配置）」）⇒ 采纳其**结构**（三区分工）
   而非**数值**，与本仓既有取向一致。

## 守护测试的设计

- **步轴**：以**不可满足的 token 预算**（`token_used=0`、`budget=10**9`）调用 `should_compact`，
  排除 token 维度 ⇒ 判据只剩步轴一项。`6` 真 / `5` 假 ⇒ 阈值语义被钉住。再断言
  `LoopContext().rounds == 0`（每轮归零的**机制**，即「轮不可表达」的根据）。
  **实测订正**：初版用 `budget=0` 想「关掉」token 维度 ⇒ **转红** —— 判据是
  `token_used >= budget`，`0 >= 0` **恒真** ⇒ token 维度反而**恒触发**；改用**不可满足**的
  大预算（`0 < 10**9` 恒真为假）才真正排除该维度。此为**隔离一个 `or` 判据的单侧**时的通用坑。
- **轮轴**：`plan_window(20, B, tiered=True).short_turns == 10` 与 `(40, …) == 20` ⇒ 边界**随总量
  缩放**（若是固定字面边界，两者会相等）。
- **不引用具体常量的数值做分支**：测试只断言**关系**（阈值处真/假、边界随总量缩放），
  故常量被合法调整时不会静默失真。

## 反证

把守护断言改成轮数读法（如 `should_compact(0, 0, 0)`，或把 `plan_window` 断言换成固定字面边界）
⇒ 转红；复原 ⇒ 绿。证明这两条锚**确实咬住**「两轴分工」这一行为语义，而非恒真。
