# Context Specification Delta — 压缩轴口径（change 0200）

## ADDED Requirements

### Requirement: 压缩轴口径（轮 / 步两轴不可互换）

系统 SHALL 区分并**分别**使用两个互不相通的时间轴；二者 SHALL NOT 互换、SHALL NOT 混算：

- **步轴（轮内）**：上下文压实的**触发判据**中，步数维度 SHALL 是**本轮内已记账的工具动作步数**
  （`LoopContext.rounds`）。该计数 SHALL 在**每个用户轮**开始时自 `0` 起算，故其取值 SHALL NOT
  携带跨对话轮的累计 —— 系统 SHALL NOT 存在以「对话轮数」为维度的压实触发面。
- **轮轴（跨轮）**：会话历史**分层**（短 / 中 / 长三层滑窗）SHALL 以**对话轮**为单位计
  （总量 `loop.history_turns`）。分层边界 SHALL 随 `loop.history_turns` **等比缩放**（比率相对），
  SHALL NOT 采用任何**字面轮数**的固定边界。

`loop.compact_steps`（缺省 `6`）SHALL 仅解释为**步轴**阈值；SHALL NOT 解释为「对话第 N 轮开始
压缩」一类的**轮轴**边界。由于步轴每轮归零，把该值读作轮轴边界 SHALL 为**非法** —— 该边界在
系统内**不可计算**（无任何用户轮计数器可据以推出）。

本要求 SHALL NOT 改变任何既有阈值或配比：`上下文自动压实` 的触发判据与
`三层窗口比例分配` 的份额常量 SHALL 各自保持其既有规格。

#### Scenario: 压实触发仅由步轴决定

- **GIVEN** token 用量为 `0` 且 token 预算**不可满足**（远大于用量 ⇒ token 维度恒不触发）
- **WHEN** 以本轮步数 `6`（等于步阈值）调用压实触发判据
- **THEN** 判据为**真** ⇒ 触发**仅**由步轴达成

#### Scenario: 步阈值之下不触发

- **GIVEN** token 用量为 `0` 且 token 预算**不可满足**
- **WHEN** 以本轮步数 `5`（低于步阈值）调用压实触发判据
- **THEN** 判据为**假**

#### Scenario: 步计数每轮归零（对话轮不可表达）

- **GIVEN** 一个新构造的循环上下文
- **WHEN** 读取其步计数
- **THEN** 取值为 `0` ⇒ 步计数自本轮起算、**不**携带跨轮累计 ⇒「对话轮数」无法由该值推出

#### Scenario: 分层边界随轮总数等比缩放

- **GIVEN** 分层启用且历史预算为正
- **WHEN** 分别以 `loop.history_turns = 20` 与 `40` 计算短层轮数
- **THEN** 两者分别为 `10` 与 `20`（短层 = 总量 × 0.5）⇒ 边界是**轮比率**、随总量缩放，
  **非**固定字面轮数
