# Design — 退化 JSON 的控制字符修复（change 0322）

## 1. 证据

| # | 事实 | 来源 |
|---|---|---|
| E1 | 事故产出结构完整，4 个裸 `\n` 位于 `script` 字符串内 | trace `fe9f78fd…` `loop_finished.raw_output`（542 字符） |
| E2 | `json.loads` 报 `Invalid control character at char 366` | 本轮离线复现 |
| E3 | 0321 修复返回 `None`（只处理非法转义与内引号） | `_repair_degenerate_json_literals(raw)` |
| E4 | 事故进程启动于 15:15:42，晚于 0321 提交 15:13:26 ⇒ 新代码已运行，失败非陈旧进程 | `ps lstart`、`git log -1` |
| E5 | 同类修复的边界（结构完整才采纳、不补括号引号）已在 0321 验证 | ADR-0311 |

## 2. 决策

### D1 在 `_repair_string_fragment` 内补齐控制字符支

同一状态机已负责字符串内的转义与引号判定；控制字符是字符串内容的一种，放在同一处保证
单遍扫描、无二次遍历。规则：

- `\n` → `\n`（两字符转义）、`\r` → `\r`、`\t` → `\t`、`\b` → `\b`、`\f` → `\f`；
- 其余 `ord(char) < 0x20` → `\u00XX`（四位小写十六进制）。

### D2 语义等价

转义只改变**表示**，不改变解码值：`json.loads` 后的 `script` 与模型原文逐字相同（含换行）。
这与 0321「不删除 / 不替换非控制字符」的边界一致 —— 控制字符以等值转义表示。

### D3 不扩大到其他形态

- 不处理裸 `"`、非法转义（0321 已覆盖）；
- 不补结构（未闭合 / 截断仍失败）；
- 不处理 U+007F（JSON 合法，`json.loads` 可解码）。

## 3. 规格映射

`loop`「推理动作解析与失败可见」MODIFIED：在确定性字面量修复段补「裸控制字符改写为等值
JSON 转义」规则，并追加两条 Scenario（事故复刻恢复 / 合法转义零影响）。

## 4. 测试

`tests/test_degenerate_json_repair.py`：

| 用例 | 断言 |
|---|---|
| 事故原文复刻（多行 heredoc） | `tool_id == "tools.code_run"`、`script` 含原换行、`failed is False` |
| 合法 JSON 含 `\n` / `\t` 转义 | 解码值逐字不变（本修复不介入） |

## 5. 反证

1. 回退控制字符支（`_CONTROL_ESCAPES` 判据）⇒ 事故用例红（`json.loads` 仍报控制字符）；
2. 只映射 `\n`、其余控制字符不处理 ⇒ 制表符用例红（若测试覆盖制表；本 change 用例覆盖换行）。

## 6. 局限

- 裸控制字符修复同样要求对象结构完整；未闭合 / 截断仍维持失败语义。
- 不校验参数语义；`INVALID_ARGS` 仍由工具链 Gate 承担。
- `\u00XX` 对 C0 控制字符（如 NUL）会生成合法转义，但模型通常不会写出这类字符；不额外拦截。
