# 0164 · hooks（钩子）架构设计 —— 事件面 · 接缝复用 · 失败处置（**零 `src/` 改动**）

## Why

用户 2026-10-07 诉求（原话）：「还有 hook 功能架构设计缺失-需要归一个 openspec」。口径已确认：
**只出规格 + ADR**（不写实现代码，实现另立 change）。

现状：全仓**没有**钩子能力，也**没有任何规格**承诺它 ——

1. **无事件总线**：`doc/01-architecture/architecture-overview.md:181` 只在「关键约束」里点了「事件总线」
   这个词，实现与规格**双双缺席**。
2. **已有的横切接缝只有两个写进规格**（`doc/openspec/specs/loop/spec.md`「横切中间件插入」）：
   `middlewares`（动作前链，**可否决**）与 `action_observers`（结果侧观察者，**仅通知**）。
   另有三个**代码注入**、规格未收的口子：`turn_observer` / `trace_observer` / `cold_path`（`loop/default.py:149-184`）
   与 `Approver`（`:43`）—— 全部只在 `runtime.py:703-723` 由组合根**代码注入**，**无配置声明面**。
3. **缺三个口子**：轮前（`turn.before`）、会话起止（`session.start` / `session.end`）、
   记忆写入（`memory.write`）—— 既无接缝也无规格。

⇒ 本 change 交付**架构契约**（规格 + ADR + 模块设计），把「钩子是什么、挂在哪、坏了怎么办、
密钥与不可逆边界在哪」一次性定下来；**实现另立 change**（在 tasks 与本提案中明写）。

## What Changes

- 新建 capability 规格 **`hooks`**（`specs/hooks/spec.md` **ADDED**：4 Requirement / 10 Scenario）。
- **ADR-0155**：钩子架构（事件面 / 接缝复用而不新建总线 / 外部命令 + 内置回调两形态 / 声明面 /
  fail-closed 与审计边界）+ 变更追踪行。
- `doc/02-modules/hooks.md`：模块设计（事件表、接缝映射表、命令协议、失败矩阵、安全边界）。
- 台账 `coding-plan/known-risk.md` §1 新行 **E101**（hooks 架构缺失 ⇒ **设计闭**、实现未闭）。
- **零 `src/` 改动、零测试改动**（无实现 ⇒ 无可运行判据；本 change 的验收＝`openspec validate` 全绿 +
  文档自洽）。

## Non-goals

- **不实现**任何钩子代码（事件总线 / 子进程执行器 / 配置解析**一律不做**）。
- **不引入通用事件总线**：先复用既有接缝；多播需求出现再议。
- **不改**既有接缝的语义与签名（`middlewares` / `action_observers` / 观察者链**一字不动**）。
- **不做** Web / Desktop 侧的钩子声明面（声明面属配置面，跨端一致另议）。
- **不引三方库**（子进程走 stdlib `subprocess`，argv 列表不经 shell）。

## 风险

1. **「规格有了 ≠ 能用」的误读**（规格先行、实现另立）⇒ 在规格 Purpose、ADR 已知局限、台账 E101
   三处**明写**「**未实现**（架构契约先行）」。
2. **过度设计**：钩子面一旦做宽（多播 / 优先级 / 异步）即成事实上的事件总线，与 P1「无特权核心」
   及「先复用接缝」的取舍相悖 ⇒ 规格**只**承诺 7 个事件与 2 种形态，扩展须先改 ADR。
3. **安全面泄漏**：钩子是**外部命令**、天然接触载荷 ⇒ 载荷脱敏（承 `scrub_key_fact` 思路）+
   子进程**不继承密钥环境** + 输出不进日志 / 记忆 / 对话，三处都写进规格（**红线**）。
4. **不可逆性**：钩子副作用**无法**建模为可逆效应（外部命令不可撤销）⇒ 规格**显式交代**此例外
   （不纳入 `EffectTracker`）并建议默认只读命令 —— 与 P2「一切副作用可逆」的**唯一**例外必须在契约里说清。
5. **接缝缺口**：三个口子（`turn.before` / `session.*` / `memory.write`）**当前没有**注入点 ⇒ 若不写明
   「实现待办」，实现者容易在 loop / store 里**硬插分支**（破坏分层）⇒ 设计里逐条标「既有 / 待新增」。
