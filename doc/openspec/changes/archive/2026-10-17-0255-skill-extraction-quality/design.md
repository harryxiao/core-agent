# Design 0255 — 技能提炼确定性质量门

## D1 确定性门先于判定门

发布路径的顺序固定为：

```
writer 输出 → redact_secrets（0254）→ 非空 → 确定性门 → 判定门（可选）→ 退役守卫 → register
```

- 确定性门**零模型调用**、纯函数，因此可**缺省开启**（不改变「未配置 JEV ⇒ 零额外调用」的
  既有承诺）。
- 判定门保持既有语义：仅在注入时执行；未过清组留痕；异常 / 缺答案 fail-open。确定性门
  先拦掉明显垃圾，判定门只处理「形式合格、内容是否值得发布」的判断。
- 空文本（`strip()` 后）保持**保留样本**（模型瞬时失败，样本留待下轮）；确定性门拒绝则
  **清组**（该批样本已产出不可用文本，重抽只会得到同样结果并放大调用）。这一区分沿用
  0198 的既有取舍。

## D2 步骤行的确定性判据

`_STEP_LINE = ^\s*(?:\d+[.、)]|[-*•])\s+\S`。计数 ≥ 2。理由：

- SOP 提炼 prompt 明确要求「编号步骤清单」，编号是模型输出的**结构契约**；
- 单步 SOP 无复用价值（等价于一条普通事实），是审计中「垃圾技能」的主要形态；
- 接受 `-` / `*` / `•` 项目符号，避免模型换列表风格即被误杀（over-accept 侧，不与发布
  目标冲突）。
- 正文长度下限 10（strip 后）拦 `ok` / `x` 之类退化输出；上限 4000 与技能库上界同源。

## D3 逐字重复拦截

在确定性门内检查 `any(s.instructions.strip() == text.strip() for s in library.all_skills())`。
只拦**逐字相同**：

- 不做相似度阈值 —— 需要 embedding / 新依赖，且阈值本身成为不可解释的发布判据；
- 同组重复提炼本就覆盖同一 `skill_id`（id 由组键派生），逐字相同 ⇒ 无需重写；
- 跨组逐字相同 ⇒ 技能库不增长，避免同一 SOP 换壳重复。

## D4 字段上界单一定义

`skills.models` 定义公开常量：

| 常量 | 值 | 消费方 |
|---|---|---|
| `MAX_INSTRUCTIONS_CHARS` | 4000 | `SkillLibrary.register` / `SopExtractor` 确定性门 / `evolution.content` |
| `MAX_DESCRIPTION_CHARS` | 400 | `register` / `evolution.content` |
| `MAX_TASK_TYPES` | 16 | 同上 |
| `MAX_TASK_TYPE_CHARS` | 80 | 同上 |
| `MAX_PRECONDITIONS` | 8 | 同上 |
| `MAX_PRECONDITION_CHARS` | 200 | 同上 |
| `MAX_SKILL_ID_CHARS` | 120 | `register` |

`evolution.content` 保留既有私有别名（`_MAX_* = 公开常量`），零行为变化；上界值不变。
`register` 越界抛既有 `INVALID_SKILL_SCHEMA`（不新增错误码，调用方兼容）。

## D5 兼容性

- 缺省 SOP 发布路径**有意变更**：单步 / 超短 / 逐字重复不再入库 —— 这正是本 change 的目的，
  写入 ADR。
- 满足确定性门的 SOP：入库字段、`skill_id`、状态、可逆效应、样本清组**逐字不变**。
- `SkillLibrary.register` 对上界内的技能（含同 id 覆盖）逐字不变；仅越界新增拒绝。
- 不新增配置键；确定性门无关闭开关（缺省部署的安全面），如需关闭须改规格。

## 反证设计

| 探针 | 期望 |

| 摘确定性门调用 | 单步 / 超短 / 重复用例红 |
| 步骤判据改为 ≥1 | 单步用例红 |
| 摘重复检查 | 重复用例红 |
| 摘 `register` 任一上界检查 | 对应参数化用例红 |
| 摘「确定性门清组」 | 清组用例红 |
