# Design 0273 — 里程碑报告锚定

## D1 复用 pinned 通道，不造第二个注入块

常驻笔记已具备本条需求需要的**全部**注入语义：整篇纳入（绝不半篇）、逐轮无条件、紧随宪法块、
`pin_priority` 决定在场次序、超预算整篇排除且 `pinned_overflow()` 可查。新增一个「里程碑块」
会造成两套预算（4000 字符各算各的）、两处 prompt 位置、两套在场判定 —— 风险显著大于收益。

因此本 change **只**产出一篇普通 canonical note（`pinned=True` + 高优先级），注入路径零改动。
「永久置顶」由此落地为「常驻块内**最靠前**」，且仍受 4000 字符总预算约束（单篇 3000 字符
⇒ 通常单独在场；与其它常驻笔记共存时按优先级前缀取舍，行为可见）。

## D2 确定性装配，零 LLM

`close_milestone` 只做拼接与排序，不调用模型：

| 来源 | 去向 | 排序 |
|---|---|---|
| `conclusions`（显式） | 结论节 | 调用方给定次序 |
| 会话压实摘要 | 结论节（段首） | 单条 |
| `decisions`（显式） | 关键决策节 | 调用方给定次序 |
| `constraints`（显式） | 硬约束节 | 调用方给定次序 |
| 该会话 keyfact | 关键事实节 | `entry.id` 升序 |

节次序固定：结论 → 关键决策 → 硬约束 → 关键事实（规格固化，不随输入变）。空节整节省略。
「是否为空」只看**非空白**条目：全空且无摘要 ⇒ `None`（不写盘）。

## D3 身份与来源守护

- `note_id = as_note_id or "milestone-" + slug_topic(milestone)`；slug 为空且未给 `--as` ⇒ `None`。
- 幂等：同 `note_id` 重复收口 ⇒ `store.update()` 覆盖同一篇，不产生第二条。
- 来源守护与 promotion 同构：既有笔记 `source != "notes.milestone"` 且未给 `--as` ⇒ `None`
  （绝不覆写人工正文）。显式 `--as` 视为授权。
- 既有笔记的 tags 并入产出（保留操作者手工标签），标题缺省沿用既有标题。

## D4 有界与脱敏

- 所有文本先 `redact_secrets`（与记忆写回同源，承 ADR-0141① 密钥红线）。
- 正文上限 `MAX_MILESTONE_CHARS = 3000`：**保留头部**（结论/决策在前，最需要锚住），截断处
  留 `…[truncated N chars]…` 标记。3000 < 常驻总预算 4000，给同场其它常驻笔记留余量。
- 上限作用于**装配后的正文**，不是单个输入——恶意/意外超长输入无法绕过。

## D5 缺省优先级 100

人工 `notes pin` 的缺省优先级是 0；里程碑缺省 **100** 表达「阶段硬约束优先于一般常驻笔记」。
操作者可 `--priority` 覆盖（含 0：仍常驻但按字典序排）。`unpin` 语义逐字不变（归零并退出常驻面）。

## D6 CLI 面

```
notes milestone <name>
    [--session <session-id>]    # 装配该会话的压实摘要 + keyfact
    [--as <note_id>]            # 显式目标（来源守护的显式授权）
    [--title <title>]
    [--priority <n>]            # 缺省 100
    [--conclusion <text>]...    # 可重复
    [--decision <text>]...
    [--constraint <text>]...
```

成功 ⇒ 回执 `已锚定: <note_id>\t[pinned 优先级 N]`、退出 0。`close_milestone` 返回 `None`
（无内容 / 派生 id 为空 / 来源冲突）⇒ stderr 报明确原因、退出 1、**不写任何文件**。
`--session` 无摘要**不**报错（keyfact 与显式条目仍可成文）；完全不存在的会话与「不传
`--session`」等价（只是没有摘要/关键事实可装配）。

## D7 不自动触发（设计裁决）

阶段结束的判定不可靠（loop 无阶段实体，编排进度事件是执行面状态、非知识面语义），且自动写入
未 review 的内容并逐轮注入会突破 ADR-0142①（notes 是刻意知识）与 ADR-0141①（常驻内容密钥红线）。
本 change 保持「显式触发」；PA-08 方案 C（自动置常驻）继续否决，须显式翻案才可再议。

## D8 反证与已知局限

反证：摘来源守护 ⇒ 覆写用例红；摘脱敏 ⇒ 密钥用例红；摘截断 ⇒ 上界用例红；忽略优先级 ⇒
在场次序用例红；空内容不返回 `None` ⇒ 不写盘用例红。

局限：

1. 阶段划分仍靠人/上层显式调用；系统不推断「里程碑已结束」。
2. 报告内容质量取决于输入与既有 keyfact；无模型归纳（确定性是有意取舍）。
3. 3000 字符上限对超长里程碑会截断**尾部**；详细内容应留在 canonical 正文后续节或另行成篇。
4. 常驻总预算 4000 不变：其它常驻笔记可能因本篇在场而被整篇排除（`notes pinned` 可见）。
