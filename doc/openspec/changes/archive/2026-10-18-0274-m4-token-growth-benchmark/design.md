# Design 0274 — M4 长任务 token 增长基准

## D1 固定任务序列

- 24 轮，每轮用户文本 **恰好 240 字符**、桩回复 **恰好 480 字符**（`_fixed` 重复填充后截断）。
  等长载荷 ⇒ token 估算（共享估计器）逐轮可复现，曲线无内容噪声。
- 任务文本带轮次编号（`任务NN：…`），桩 provider 从当前用户消息派生回复（`完成NN：…`）
  ⇒ 无隐藏状态、无调用计数耦合。

## D2 探针与采集点

- 每轮 `astream` 消费完毕后读 `LLMPlanner.last_prompt_tokens()` —— 该探针取「装配全量估算」
  与「provider 实报 `prompt_tokens`」的较大者（`0152` / ADR-0144），覆盖系统提示、摘要块、
  历史消息与工具 schema。
- 选用 `astream` 路径（生产主路径）；桩 provider 的 `astream` / `acompletion` 同源同输出。

## D3 外置运行 vs 线性基线

- **外置运行**：`MemoryStore(summarizer=有界摘要器)` ＋ `maintenance_interval=1.0` ＋
  `history_turns=20`（生产缺省）＋ 注入步进时钟 ⇒ 每轮维护节拍产出会话摘要与中层摘要，
  下一轮 `_load_summaries` 见到摘要 ⇒ `plan_window(tiered=True)` 切成短带 10 轮 / 中带 6 轮。
- **线性基线**：同一循环、同一任务序列，但关闭摘要器与维护节拍（`maintenance_interval=0`）
  且 `history_turns=count` ⇒ 全量原文回灌，逐轮线性增长（对照组，不假设「无记忆」）。
- `token_budget=65536`（生产缺省）⇒ 预算闸门不介入单轮（每轮独占约 700 tokens），
  只测**装配增长**，不测终止语义。

## D4 有界摘要器（模型有界输出的确定性替身）

```python
def _bounded_summarizer(material):
    return "；".join(e.content for e in material)[-_SUMMARY_CHARS:]
```

- 生产摘要器是 LLM 调用（输出有界）；替身以「保留合并内容尾部 600 字符」模拟**有界滚动
  摘要**。若替身无界拼接，摘要本身会线性膨胀 —— 那是替身的缺陷，不是被测机制。
- 纯本地、无网络、无随机、无时钟依赖。

## D5 判据（机制性，不设绝对阈值）

- 远期饱和：窗口（短带 10 轮）与两层摘要到界后，逐轮装配占用**恒定**
  （末 8 轮 `max - min == 0`）。
- 次线性：外置曲线整体最小二乘斜率 < 线性基线斜率，且末轮占用 < 基线末轮。
- 确定性：同一 harness 两次运行曲线逐值一致。
- **不做**绝对 token 阈值 / CI 门禁（PA-10 选项 C 未采纳）。

## 反证

1. 临时让 `DefaultLoop._load_summaries` 恒返回 `("", "")`（摘要不注入 ⇒ 不分层）⇒
   远期饱和与斜率判据转红；复原后全绿。
2. 临时移除维护节拍（外置运行 `maintenance_interval=0`）⇒ 无摘要 ⇒ 同上转红。
3. 基线对照保持线性 ⇒ 证明斜率比较不是「两段全平」的空过。

## 已知局限

- 合成文本以中文为主，token 估计器口径与真实模型 tokenizer 不同；本基准测**同一口径下的
  相对增长**，不是绝对成本。
- 摘要替身不模拟真实 LLM 摘要的信息损失；只验证「有界外置」这一结构性质。
- 24 轮、单一任务形态覆盖不了工具调用轮（多步 ReAct）与多会话交错；后者由单测覆盖。
