# design — 0087 pet 微任务真实化与空闲自治睡眠

## 决策

### ① 任务**一次性**：`wake()` 消费队首（`popleft`）

今天 `wake()` 只读 `_tasks[0].goal`、**不出队**，空队列时**编造**一个「闲逛探索」任务 ⇒ 宠物永在空转。

- 「干完无任务就睡」（用户诉求）**要求任务可完成** ⇒ 必须出队。
- 规格「重复简单任务」指宠物**支持这类可重复的琐事**（不断被派发），**非**「同一任务实例永远重复」。
  要与既有实现（不出队）解耦：既有行为是**实现选择**，规格未明文要求实例常驻。
- **代价（已核实并接受）**：两条既有测试断言了「不出队」，按新语义改写（`test_wake_stays_silent_off_feedback_cycle`
  改派 3 个任务以维持其真实意图；`test_session_snapshot_restore_roundtrip` 改派 2 个任务、唤醒一次后断言剩 1）。

已否决 **保留不出队 + 另设 `clear` 才入睡**：那样「干完」永不发生，宠物只在主人显式清空时才睡 ——
与用户「**干完**无任务也可以自己睡觉」直接冲突。

### ② 空闲 = **让行态**（`_yielding`），不新增枚举

规格明文「仅四态」「让行复用 orchestration `SUSPENDED` 语义」。故入睡即置 `_yielding = True`：

- **宿主驱动零改**：`PetWakeDriver.tick()` 已把 `PetError` 当预期态 `skipped`（`0083`），入睡后唤醒抛
  `PET_YIELDING` ⇒ **天然跳过**，不空转、不刷屏。
- **新任务自动唤醒**：`dispatch()` 追加任务后清 `_yielding`（「新工作唤醒让行中的宠物」，与既有 doze/resume 同构）。
- **持久化自洽**：`snapshot()` 已含 `yielding` ⇒ 睡着的宠物恢复后仍睡着。

已否决 **新增 `SLEEPING` 枚举态**：与规格「仅四态」冲突，且要改驱动 / 快照 / 恢复 / 全部状态断言 —— 为一个
可与让行同构的概念付全额税。

### ③ 微任务**真实化**：真探才有产出，否则 `None`

与 `0086` 同口径：**返回值必须有事实依托**。三条任务各自的真实来源：

| 任务 | 真实来源 | 不真时 |
|---|---|---|
| `terminal_walk` | 读命令历史（`$HISTFILE` / `~/.bash_history`）并**只数非空行** | 文件不可读 / 计数 0 ⇒ `None` |
| `system_hint` | `os.getloadavg()` 真负载 | 不可用 / 负载 **< CPU 数**（不显著）⇒ `None`（不打扰） |
| `nonsense_comment` | 经注入的 `comment_writer` **真写回** | 无 writer ⇒ `None` |

- **只报条数、绝不外泄内容**：命令历史可能含密钥 / 隐私；对齐「密钥只引用不读取」的取向 ⇒ 产出文案只含**计数**。
- **可注入**：`walk_probe` / `hint_probe` 缺省接真实探测函数（同 `sleep=time.sleep` / `clock=time.monotonic`
  的注入先例），测试注入确定替身 ⇒ 不受运行环境（无历史文件 / 负载高低）影响。
- 已否决 **保留预制文案**：正是 E26 记名的谎报；已否决 **删掉两条假任务**：规格明列这三条。

### ④ 触发点 = **空闲入睡前的过渡点**，且**有通知面**才跑

`_go_idle()` 在「队列清空」那一次调用：置让行态 + 有 `notifier` 时跑一次微任务并上报其真实产出。

- 契合规格 R14「宠物**空闲**触发日常微任务」——「空闲」= 队列清空的过渡。
- **无 notifier 不跑**：无声明通知面时跑有副作用的微任务（如写注释）没有意义，同 `0086`「无 notifier 不跑惊喜」。
- **fail-soft**：微任务异常被吞掉，不阻断入睡（非关键路径，同 `0086` 惊喜 / loop `action_observers` 先例）。

已否决 **每次唤醒都跑微任务**：那是「不空闲」也在摸鱼，且唤醒成本翻倍。

### ⑤ 注入面走**可调用体**，不让 `core/session.py` 依赖 `microtask`

`PetSession` 收 `microtasks: Callable[[], str | None] | None`（组合根传 `runner.run`），与 `notifier` /
`busy` 同一惯用法：会话层不 import 具体微任务实现 ⇒ 层间解耦，且 `test_architecture` 的分层约束不受影响。

## 影响面

- **驱动（`0083`）零改动**：入睡 ⇒ `PET_YIELDING` ⇒ `skipped`，正是既有语义。
- **CLI `pet run`**：宠物干完活后不再空转，`tick` 逐轮 `skipped`（宿主可见）。
- **`0088` 控制面**：`sleep` 动词 = `suspend()`、`wake` 动词 = `resume()`、`assign` = `dispatch()` —— 本变更
  已把这三者的语义（含「dispatch 自动唤醒」）落定。
