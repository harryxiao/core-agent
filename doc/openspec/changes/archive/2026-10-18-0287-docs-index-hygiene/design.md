# Design 0287 — 文档卫生

## D1 为什么 PA-11 取「补索引 + 守卫」而不是只补索引

`0226` 已实证索引漂移会**直接造成返工**：走查按 README 的 `phase-0~34` 范围找账，
漏掉 `phase-36`（长任务硬化）与 `phase-38`（四维记忆蓝图查漏补缺），把已裁决事项重报为缺口。
只补一次索引仍会再漂；一条断言把「新增 Phase 忘补索引」从静默漂移变成门禁转红。

## D2 计数口径改成可机读、无歧义的 46 份

旧句「36 份 Phase 文档（README + phase-0~34…）」本身就算不平：`phase-0`~`phase-34`
是 35 份，加两个补丁是 37 份，再加 README 是 38 份。新口径直接对齐**仓库内**文件：

- `phase-*.md` 共 **46** 份；
- 其中主文档（`phase-N` / `phase-N.N`）**43** 份，最大 `phase-41.md`；
- 配套记录 **3** 份：`phase-1-contracts-baseline.md` / `phase-17-impl-notes.md` /
  `phase-21-findings.md`；
- 本地未跟踪、按约定不提交的 `phase-32.md` / `phase-3-prompt.md` **不计入**（守卫硬编码排除）。

守卫解析 README 中唯一一行「索引计数（守卫）」，与实际 glob 逐项比对。

## D3 §1 覆盖判据按「主文档」而不是「README 任意位置出现」

新 Phase 很容易在正文提过、却忘了加 §1 索引行 —— 只查全文包含会漏掉这种「正文提过、索引
没列」的半漂移。守卫因此解析 §1（`## 1.` 到 `## 2.`）表行里的反引号文件名，要求集合与
**仓库内主文档**集合相等。这样新增 Phase 时，补正文但忘补索引表也会红。

## D4 PA-12 只改 §0 批内缺口前缀，不改路线图与历史

批内缺口与「记忆三面路线图」是两套独立编号。选 B：把 `phase-38.md` §0 的三行改为
`B38-1 因果` / `B38-2 接线` / `B38-3 谓词面`（`B38` = Batch 38），并在表下加「非同组」注记。
§118 的「记忆三面路线图 G1~G5：全闭」是历史收官声明，逐字保留。全局重编号（选项 C）
会波及 ADR / 台账 / change，明确不做。

## D5 登记簿的「已闭」与结构守卫兼容

`tests/test_arbitration_ledger.py` 要求标「已闭」的总表行带 change 号，并要求第二轮每条
仍有「现象/证据/可选项/建议/落地面」。因此 PA-11 / PA-12 只在 §1.2 行尾追加
「**已闭**（change `0287` / ADR-0277 / 台账 E223）」，§2 逐条小节**保留原文**并追加收口段。
测试里把 `_ROUND2` 的注释从「开放项」订正为「第二轮项（含已闭）」，不改断言。

## D6 销 known-risk 的「README 已知项」

`known-risk.md` 原有一行把「README §2 标 ✅ 与事实不符」记成**已知**。PA-11 的落地面要求
销掉它。订正口径：✅ 表示 **Phase 计划完成**，不表示 `composition` / `distributed` 整包已
生产接线；缺口本身仍由该行承载。这样既不掩盖缺口，也不再把索引漂移当免检项。

## 局限

- 守卫只覆盖 `coding-plan/README.md` 与 `phase-*.md` 的计数/覆盖，不校验每行描述是否过时。
- 配套记录改名为主文档、或新增非 `phase-*` 命名的主文档时，需同步测试口径。
- `phase-32.md` / `phase-3-prompt.md` 按约定不提交，守卫硬编码排除；若将来入库须同步计数。
- `B38-*` 只消除 §0 批内歧义；`phase-38.md` §118 仍保留路线图 `G1~G5`（有意，历史声明）。
- 文档不回显任何密钥、任务正文或用户路径。
