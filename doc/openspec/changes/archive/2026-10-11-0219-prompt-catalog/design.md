# Design 0219 — 内置提词总表 ＋ pin 补 3 条

## §1 根因

| 缺口 | 取证 |
|---|---|
| 3 条 prompt 未 pin | `tests/test_prompt_pinning.py` 覆盖 9 条；⑧ 晚于 `0215` 新增（ADR-0205 局限②已登记）、⑪⑫ 有意未纳 |
| 无集中查阅面 | prompt 散在 12 个模块的私有常量；「写了什么／在哪／有无 pin」须逐个 grep |

## §2 取舍

- **§2.1 落点 = 文档，非代码模块。** 用户裁决「只出文档总表」。把 prompt 收拢进 `src/core/prompts.py`
  会触及 ADR-0205「prompt 是**实现细节**、不外露」的既立口径（且 pin 的「独立副本」价值被削弱
  —— 副本与真源同文件则改一处即同改）。故**代码零改动**，文档只做镜像。
- **§2.2 文档定位 = 现状快照（镜像），显式标注非真源。** 否则读者会误以为改文档即改行为。
  §0/§6/§7 三处明写「真源 = 模块常量 ＋ pin 副本」「改一条 = 三处同改」。
- **§2.3 pin 补 3 条，不补 ⑬。** ⑬ 宠物人格是 `render_prompt()` **动态拼接**（`name`/`species`/
  `traits`/`persona_text` 随档案变），逐字 pin 无稳定锚；如将来需要，宜按「固定槽位结构」pin。
- **§2.4 分类口径显式声明为「解释性」。** 「控制面/数据面」在仓内另有既定含义（pet 控制面、
  分布式/进化 控制面·执行面分离）；本表 §0 明写这是**本表**的归类，避免与正式术语冲突。
- **§2.5 安全承重措辞单独标注。** ⑤⑥（关键事实／关系）的「绝不输出明文」是「密钥不落记忆」
  第一道防线，表格与 §7 指引均单列警示。

## §3 影响面 / 可逆性 / 红线

- **影响面**：`tests/test_prompt_pinning.py`（12 → 16 用例）＋ **新** `doc/03-interfaces/prompts.md`。
  **零 `src/`**。
- **可逆性**：纯测试 ＋ 文档，无副作用、无需 `EffectTracker`。
- **红线**：不动任何 prompt 措辞（逐字 pin 保证）；`exclude_source_prefixes` 等 phase-26 红线不涉；
  零三方依赖；四门禁直连二进制。

## §4 已登记局限

1. **文档会漂移** —— 改 prompt 若忘同步本表，表与真源不一致（pin 测试**拦不住**文档漂移，
   只拦代码）。缓解：§0/§7 明写三处同改的纪律。
2. **⑬ 仍未 pin**（动态拼接）。
3. **只覆盖 prompt「头」** —— 动态拼接的块正文（如 ① 的 11 块、④ 的既有摘要节选）由结构不变量
   与既有单测覆盖，本表只做**描述**，非 pin。
