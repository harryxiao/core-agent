# pet 唤醒由宿主驱动（pet-host-driven-wakeup）

## Why

账本 **E17**（E4 收口时记后续：「宠物仍显式 `wake()`，无自建调度线程」）：`PetSession.wake()` 在生产**零调用方**
（仅 `tests/test_pet_core.py`），而接口 §5 与模块文档都写着「主循环之上叠加**后台自治调度**」——读者会以为
内核里有个常驻调度者，实际上**没有**，且**规格也没有要求**。

**一手核实（三条，决定本变更的形态）**：

1. **规格无 daemon 条款**：`specs/pet-mode/spec.md` 的 Lifecycle 只写
   「**每次唤醒**复用 `Loop.run()` 同步薄壳（asyncio.run 桥接）**逐次执行**」；「Low-Priority Yielding」
   明写让行模型是「**同步 + 锁（RLock）**」、宠物**让行不抢锁**。规格从未出现 daemon / 调度线程 / 周期驱动者。
2. **文档自述即「不常驻」**：`pet-mode-interface.md:138` 与 `pet.md:39` 均写「逐次执行**不常驻**」——
   「后台自治调度」一词是文档层的**过度承诺**（无组件承载），与 E19（durability 过度承诺）同型。
3. **架构事实否决进程内 daemon**：`core-agent pet <verb>` 是一次性进程（`entry._pet`：`build_runtime` →
   `activate_from_cli` → 打印 → **退出**），进程内起线程**必随进程立即结束**——在那里 daemon 化是**错误解法**；
   能承载常驻驱动的只有长驻宿主（`core-agent ui` 的 `serve()`）。

**用户裁决（2026-10-05）：规格中性收口** —— 不实现 daemon，把「唤醒由宿主驱动、内核不常驻」写成已知语义。

## What Changes

- `doc/03-interfaces/pet-mode-interface.md` §5：表后新增「驱动归属」登记块 —— `wake()` 是同步薄壳、由**宿主**按周期
  调用；内核不自建调度线程，三条理由（规格无条款 / 一次性进程无法承载 / 仅长驻宿主可承载）。
- `doc/02-modules/pet.md` §3.2 + §4：同口径登记（唤醒由宿主驱动；闭环的驱动者是宿主）。

## 规格中性（`.openspec.yaml: schema: spec-driven + skip_specs: true`）

**规格不需要改**：本变更是把「内核无 daemon」这一**既存事实**登记为已知语义 ——
规格既没承诺 daemon（无条款），也没被实现违反（`wake()` 与「同步薄壳 / 逐次执行 / 让行不抢锁」逐条相符）。
「文档里没有的组件不要假装有」属文档层订正，非行为变更。

## 明确不做

- **不实现 `PetDaemon` 线程**（用户裁决）：规格无此要求；且唯一的部署形态 `pet <verb>` 一次性进程承载不了它，
  为一条**没有宿主的需求**引入线程生命周期、退出收敛与配置门控，属投机（CLAUDE.md §2）。
- **不改 `pet <verb>` 为「激活后立即唤醒一次」**：那是**新增生产行为**（规格未要求「启动即执行」；
  且让 CLI 变慢/产生真实模型调用），需另立变更。
- **不改规格、零 `src/`、零 `tests/` 改动**：纯文档登记。
