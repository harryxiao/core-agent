# Design 0228 — 文件工具 `~` 展开

## D1 属缺陷修复、非新能力 ⇒ 无条件生效（不设门）

字面 `~` 目录不是任何合理用法；模型写 `~/…` **无条件**指家目录。与 `0220`（`strip_fence` 兜底）
同类：修的是「意图与行为背离」，不引入**可选**行为 ⇒ **不设配置键**。区别于 `0206` 的 kill-switch
（那个门保的是**既有**在用能力；本处的既有行为是**缺陷**，翻默认不适用）。

## D2 落点 = 工具入口、动作前展开一次

`Path(path).expanduser()` 在 `handler` 入口做一次，**展开后**的路径用于实际 I/O **并存入撤销快照**。

理由：撤销闭包 `_restore(snap)` 按 `snap["path"]` 恢复 —— 若快照存**未展开**的原串，撤销会恢复到家
目录**之外**的字面 `~` 路径（与写入点不一致 ⇒ 撤销失效 / 误建）。故「展开一次、全程一致」：
I/O 点与撤销点取**同一个** `Path`。

`_restore` 自身**不改**（快照已存展开路径 ⇒ 它天然正确）。

## D3 只覆盖 `~` 展开，不引入其它路径语义

- 不做 `resolve()`（会解软链、改相对路径语义）；
- 不做 `abspath`（不改相对路径基准，与既有行为一致）；
- 不做环境变量展开（`$HOME` / `%USERPROFILE%`）；
- 不改沙箱 / 权限的相对路径基准。

最小语义：`~`（及 `~user`，由 `expanduser` 一并处理）→ 家目录。

## D4 返回体仍回**输入**路径（contract 不变）

`file_read` / `file_write` / `file_patch` 的返回 `{"path": …}` 保持**模型给的原文**（`~/x`）——
形状与值域语义不变，仅**落盘位置**改变；避免为「回显解析后路径」引入契约变更（若将来确需，另立
change）。

## 规格

`tool-use` spec **不约束**文件工具路径语义（该 spec 覆盖：工具定义与注册 / 参数校验 / coeffect 契约 /
撤销回滚 / 超时上限 / 异步 / 插件安装 / 内置原子工具（**代码执行·网页读取**）/ 质量门禁 —— **无文件
工具专属 Requirement**）⇒ **规格中性**（`skip_specs: true`）。行为在
`doc/03-interfaces/tool-use-interface.md` §3 落注。

## 反证

摘 `_expand` 的 `expanduser`（还原 `Path(path)`）⇒ 家目录用例红；复原 ⇒ `md5sum` 逐字节同。

## 局限

1. **只展开 `~`** —— `$VAR` 与相对路径语义不动（最小语义的刻意边界）。
2. **`code_run` 的 `cwd` 未纳入** —— 非 `file_*` 工具；同源缺口（同样不展开 `~`），登记为**后续候选**。
3. **沙箱/权限的相对路径基准仍是进程 cwd** —— 展开后的绝对家目录路径走既有判定，无新暴露面；
   对宠物 loop 而言 `~/…` 展开后落在 `SafetyBounds`（cwd 白名单）**之外** ⇒ 从「写进字面 `./~`」
   变为「**被正确拦截**」（安全方向的改善，非回退）。
