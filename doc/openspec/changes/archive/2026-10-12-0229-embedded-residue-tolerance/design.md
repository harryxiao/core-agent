# 0229 design — 形态 5 判据收窄

## D1 判据 = 「余部是否含词元」，一个纯函数、两处朝向相反

新 `_has_word(text) -> bool`：`any(ch.isalnum() for ch in text)`。Python 的 `isalnum()` 对字母 /
数字 / **CJK** 皆真 ⇒ 「余部是否含**可读词元**」。

- `_embedded_action_payload`（形态 5）：余部**含**词元 ⇒ 命中（只是追加了**正文**）。
- `_trailing_json_object`（形态 3 尾部对象）：余部**不含**词元 ⇒ 接受（残渣可忽略）。

同一谓词、朝向相反 —— 即「**残渣与正文的二分**」。规格以「仅由结构性符号构成的余部 ⇒ 退化残渣」
表述，**刻意不采用闭合白名单**（理由见 D5）。

## D2 `{` 开头分支：先试「首个对象 + 残渣」

`_parse` 的 `{` 开头分支此前只有 `json.loads(整串)` 一条路 ⇒ 一个多余 `}` 就让整串 `Extra data`
失败。改为：

1. `_leading_object(text)`（`raw_decode(text, 0)`）解码**首个**对象；
2. 若成功 **且** `not _has_word(text[end:])` ⇒ 直接 `_from_dict(obj)`（**形态 2 容残渣**）；
3. 否则走既有 `json.loads` → 失败则 `_first_brace_reply`（成因措辞**逐字不变**）。

第 2 步对**任意**首个对象成立（不止含 `tool_id` 者）：`{"reply": …}` + 残渣 也一并归一，
避免造出「同一谓词、两种朝向、三种结论」的新不对称。

## D3 `_trailing_json_object` 必须**同一谓词同时改**，且**去掉「须以 `}` 收尾」门槛**

两处改动缺一不可，且互相咬合：

1. **同步收窄**。若只收窄 `_embedded_action_payload` 而不动 `_trailing_json_object`，则「正文 +
   动作 JSON + 残渣」（如 `正文 … {"tool_id": …}}`）的链路变成：`_trailing_json_object` 因余部非空
   返回 `None` → `_unclosed` 不命中（对象是闭合的）→ `_embedded` 因收窄**也不命中** → 落到
   `return Action(args={"reply": text})` ⇒ **整段当答复、动作丢失、记为成功** —— 正是 0222 /
   ADR-0212 修掉的**静默零执行**。
2. **去掉前置门槛 `tail.endswith("}")`**。该门槛把「余部」硬性限定为「以 `}` 收尾」，而残渣可
   为**纯标点**（`…}。` / `…};`）⇒ 这类输出仍会落到同一个静默零执行。改为**只**按
   `_has_word(tail[end:])` 二分后，「尾部对象 + 残渣」的容差与形态 2 **完全同源**：
   `{"tool_id": …}` 之后是**任何**无词元的余部 ⇒ 一律执行。

两处合起来才是「残渣二分」的完整落地；**实测见反证 ②**（只还原第 1 处 ⇒ 含 `}` 残渣的用例红；
连同第 2 处一起还原 ⇒ 纯标点残渣用例**再**红一条）。

## D4 无条件生效、不设门

修的是「意图（交出动作）与行为（丢弃动作）」的背离，不是新增可选能力 ⇒ 同 0206 / 0210 / 0228 判例
（**缺陷修复**），不设配置键。也**不**顺手打开 `loop.parse_retry`（那是 0227 的独立门，缺省关的语义
本轮不动）。

## D5 残渣用「无词元」而非闭合白名单：代价不对称

- 用「无词元」：余部若为**纯符号的****真**解释（如 `→`、`……`、`。`）也会被当残渣 ⇒ **执行**；
- 用闭合白名单：更严，但会漏掉未枚举的残渣形态 ⇒ 继续误杀完整动作。

本缺陷的代价（整轮报废、`failed=True`、5.6 分钟级工作全部丢弃）远高于「偶发执行一个此前也会被
当动作的对象」的代价；且 0222 真正要防的**解释性正文**必然**含词元**，被 D1 完整保留。
**结论**：取「无词元」。

## D6 与 0222 / 0227 的关系（不重开裁决）

0222 的裁决是「**JSON + 真正文** ⇒ 可见失败，不做启发式猜测」—— 本 change **不推翻**它，只是补上
它**误伤**的退化残渣（判据过粗导致的假阳性）。0227 的成因措辞条款（「含对象在前、正文在后」）
**逐字不动**：收窄后，能走到那句措辞的必是**含词元**的余部 ⇒ 措辞**首次与事实相符**。

## 规格

`loop` **MODIFIED**：形态 2 加「允许其后跟随退化残渣」子句；形态 3 的「允许以 Markdown 围栏收尾」
扩为「允许其后跟随退化残渣（与形态 2 同一定义，含围栏收尾）」；形态 5 加「『正文』限定为含词元的
余部、仅残渣 SHALL NOT 命中」子句；**ADDED 2 Scenario**（残渣不阻止执行 ＋ 残渣容错不适用于含词元
内容）。既有 16 Scenario **逐字保留**。计数：**6 → 6** req、**89 → 91** scen。

## 反证（实测）

1. 把 `_has_word` 恒返 `True`（= 还原旧判据）⇒ 残渣用例转红、含词元用例仍绿 ⇒ 断言**只**被收窄锚定；
2. **两段分别还原 `_trailing_json_object`**：
   ① 保留「须以 `}` 收尾」门槛、只把余部判据还原为「非空白」⇒ 「正文 + 动作 + `}` 残渣」用例红；
   ② 连同门槛一起还原 ⇒ 「正文 + 动作 + 纯标点残渣」用例**再**红一条 ⇒ D3 的两半各自被锚定；
3. 复原 ⇒ `md5sum` 逐字节相同。

## 局限

1. 判据是「无 alnum 词元」而**非**闭合白名单 ⇒ 纯符号的「真解释」会被当残渣（D5 的刻意取舍）；
2. 只作用于**首个 / 尾部**对象的**余部**判定，不改 0222 对「动作 JSON 在真正文**中间**」的拒绝
   （`正文 + 动作 JSON + 正文` 仍失败）；
3. 动作得以执行**不等于**该轮成功 —— 本次事故的目标路径（`2026-10-13-0229-…/`）**父目录不存在**，
   执行会得到 `EXECUTION_FAILED`；但那是**可见的工具错误**、ReAct 下一轮可自愈（模型可先 `mkdir`），
   与本缺陷（整轮报废、零执行）不是一回事；
4. `loop.parse_retry` 缺省仍**关**（不在本 change 范围）。
