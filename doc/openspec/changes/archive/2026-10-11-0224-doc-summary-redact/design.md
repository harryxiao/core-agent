# 0224 设计 — 文档摘要落盘前无条件脱敏

## D1 为什么在**写入侧**脱敏（而不是只在提示里要求）

沿 `0155`（结构化抽取）确立的判据：**「靠 prompt 让模型别写密钥」不可审计** —— 模型是否照办无从
保证、也无从测试。故承重防线必须是**确定性、可在测试中钉死**的一侧：`_doc_summary_note` 写盘前
无条件 `redact_secrets`。提示措辞（C）是**纵深**，不是防线本体。

## D2 为什么复用 `core.memory.redact_secrets` 而非新写一个

- 口径必须与仓内其余持久面**一致**：`loop.failure_digest`、`memory` 抽取/情境链均走它 ⇒ 新写一份
  只会引入漂移（哪些形态算密钥两处不同步）。
- 依赖方向无新意：`entry.py:67` **已** `from core.memory import …` ⇒ 只多引一个符号。
- 它是 pure helper、无 LLM/rag 抽象 ⇒ 不触 ADR-0048 的依赖方向。

## D3 脱敏**只作用于摘要正文**（不碰 `note_id` / `title`）

`note_id = doc-<slug>` 由 `doc_id` 确定性派生，是**幂等覆盖的键**；`title` 亦来自 `doc_id`。
脱敏若波及键，会**改变派生确定性**（同 `doc_id` 两次落盘得到不同 `note_id`）⇒ 破坏幂等。故脱敏
边界严格限于模型产出的 `summary`。

## D4 为什么不改 `rag` 规格

`rag` 规格承诺「把该文档**全文**交给一次模型调用」—— 本 change **不动**送模型的材料（送进去的
仍是全文），只脱敏**产物**。改送模型材料（如先脱敏再送）会削弱摘要质量且违背既有承诺，**不做**。

## D5 局限

- `redact_secrets` 是**形态匹配 + over-redact**：仅覆盖 `_SECRET_PATTERNS` 所列形态与「长随机串
  兜底」；**不保证**捕获一切敏感信息（如无固定形态的业务密文）—— 与仓内其余脱敏面**同一天花板**。
- `sop.py::observe` 把同一批未脱敏 `steps` 喂 `build_sop_prompt` 的**既有**暴露面**不在本 change
  范围**（登记于 ADR-0213 局限②；本 change 只闭「文档摘要 → 结论笔记」这一条）。
- 提示措辞（C）无法被测试证明「模型照办」⇒ 只作纵深，不计入防线。
