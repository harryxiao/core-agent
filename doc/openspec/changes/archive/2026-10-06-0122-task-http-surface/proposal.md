# 提案 — 编排任务的 HTTP 面与 Web 任务区（change 0122 / phase-29 change B：E53）

## 背景

`coding-plan/phase-29.md` 立账的可见性缺口 **E53**（用户需求②后半「web/app 动态显示子 agent 主题 +
运行状态」的**消费面**）。phase-29 §6 已裁决本 Phase 拆为四个 change，本 change 是 **B：HTTP 面 + 前端**
（A=E51 事件回流 ✅ 已落地 change `0121` / ADR-0114；C=E50 策略层；D=CLI 只读呈现面）。

| # | 一手事实（2026-10-06 复核，行号已核实） | 后果 |
|---|---|---|
| 1 | `ui/api.py:188-196` `UIAPILayer.run_task` **已**把编排事件映射为 `task.*` SSE（含 change `0121` 新增的 `task.subtask_progress`） | **转发层已存在且完好** ⇒ 缺的不是事件转发（订正 phase-29 §0.6 E53 行） |
| 2 | `ui/fastapi_serve.py:171-182` 注册 **11 端点**，**无 `/task` 路由** | HTTP 面**未暴露**编排入口；`run_task` 的生产消费者**只有 CLI**（`ui/repl.py:509-525` `/task`） |
| 3 | `frontend/src/`（3 视图：`Chat` / `SessionList` / `Settings`）+ `lib/api.js`（无 task 导出） | Web **前端为零** —— `task.*` 事件即使外发也无人消费渲染 |
| 4 | `frontend/src/App.svelte:43-45` 右栏 = `SessionList`（change `0116` 会话列表面） | 右栏是**会话**（持久记录）的呈现位；任务（**在途**运行态）无呈现位 |
| 5 | `orchestration/scheduler.py:399-410` 子任务事件 `payload` 含 `goal` / `acceptance` / `reason` / 里程碑白名单字段 | 任务区**可渲染**的内容（子任务标题 / 状态 / 详情）**已全部在事件载荷里**，无需新数据面 |

**契约面现状（能力缺口，非缺陷）**：`ui` spec 有三模启动、Web SPA、会话列表面等 Requirement，但**无一条**
规定编排任务在 HTTP 面的暴露与在 Web 上的呈现 ⇒ 「web/app 动态显示子 agent 主题 + 运行状态」在 **ui
层**是空白。按本仓 SDD 惯例 **规格先行**（新增能力 ⇒ **ADDED**，先例 change `0028`；**非** `skip_specs`）。

## 变更目标

**`ui/spec.md` ADDED Requirement「任务编排的 HTTP 面与 Web 任务区」**：

1. **HTTP 面暴露** —— 统一后端 API 层 SHALL 经 `POST /task` 以 **SSE** 流式返回 `task.*` 进度事件
   （与 TUI `/task`、CLI `task` **同一编排器、同一事件面**，不另造事件）；未登记会话标识 SHALL 仍被
   拒绝（`UI_SESSION_NOT_FOUND`）；编排器未注入 ⇒ `UI_ORCHESTRATOR_UNSET`（结构化错误帧，不裸抛）。
2. **任务区与会话列表并列不混池** —— SPA SHALL 在右栏**位置**提供**任务区**（复用右栏，改判见下），
   与会话列表**并列而各自独立**：任务是**在途**运行态、会话是**持久**记录，二者 SHALL NOT 合并为同一
   列表（混池会把「运行中的任务」误当「可切换的会话」）。
3. **子任务标题 + 状态 + 详情** —— 任务区 SHALL 逐子任务呈现**标题**（子任务 `goal`）与**状态**
   （待执行 / 运行中 / 完成 / 失败），并可展开查看该子任务的详情（里程碑 / 验收理由 / 失败理由，
   取自既有事件载荷）。
4. **收尾回落** —— 任务收尾（`task_finished` / `task_failed`）⇒ 该任务 SHALL **移出在途列表**（任务区
   回落至空态），SHALL NOT 因收尾而进入会话列表（任务不产生会话）。
5. **不在本需求内**（明写以免误读）：**进入子 agent 会话 / 主-子焦点切换** —— 子 Agent 消息流**无数据源**
   （转录只注入主 loop，change `0115` 明文；`ctx.messages` 不跨回合），SHALL NOT 在本需求内实现（phase-29
   §7 红线②要求先裁决与 `0115` 的边界冲突）。

## Non-goals

- **不建新事件**：复用 `UIAPILayer.run_task` 既有映射（事实 1）；`task.*` 事件名与载荷**零变更**。
- **不动编排层**：`TaskScheduler` / `subtask_progress` 白名单（change `0121`）逐字不动。
- **不动会话列表与会话转录**（change `0116` 的右栏会话面、`0115` 的转录面**零改动**）。
- **不建子 agent 会话视图 / 主-子焦点切换**（无数据源；见上「不在本需求内」）。
- **不动 CLI/TUI 呈现**（phase-29 **change D**）。
- **不动 E50 调度策略**（难易度 / `max_concurrency` 接线 = phase-29 **change C**）。
- **不引入前端测试基建 / JS 构建链改动**（`vite` + `svelte` 既有；`frontend/dist/` 为 gitignore 产物）。

## 判据与取舍（判据订正 1 条 + 范围裁定 1 条）

**(a) 判据订正**：phase-29 §0.6 原把 E53 归因为「`fastapi_serve` 无 subtask 消费 ⇒ 缺事件转发」。
复核后：**转发层已在**（`api.py:188-196`），真缺口是 **① HTTP 未暴露** + **② 前端为零**（事实 2/3）。
本 change 据此只补这两面，**不碰**转发层。

**(b) 范围裁定 —— 前端「子 agent 详情面板 + 主/子切换」收窄为「任务区内的子任务详情（可展开）」**：
phase-29 §3.3 草记 Web 侧含「主/子切换」，但 §0.6 E52 行已坐实**子 agent 消息流无数据源**；§4 裁决点③
（已认可）只对 CLI 收窄、对 Web 只定「复用右栏位置、不与会话列表混池」。故本 change 的「详情」= **事件
载荷内可见的字段**（里程碑行 / 验收理由 / 失败理由），**不**造第二数据源、**不**做焦点切换（§7 红线②）。

**(c) 右栏排布**：任务区与会话列表**同处右栏、上下两个独立区块**（任务区在上）。「复用右栏位置」取
「同一列、独立区块」义；**不**取「替换/覆盖会话列表」义 —— 后者会让在途任务挤掉会话导航，与「不混池」
所防的问题同型（把两类生命周期不同的对象争同一呈现位）。

## 风险与对策

| 风险 | 对策 |
|---|---|
| SSE 长连任务流被打断 / 客户端断开 | 与 `/run` 同型（既有 SSE 语义）；本 change **不新增**重连协议（沿用 SPA 既有行为） |
| 任务区与会话列表混池（把在途任务当会话） | 规格明写「并列不混池」+ 收尾**回落**（不进会话列表）；实现为**两个独立组件**（`TaskPanel` / `SessionList`） |
| 事件载荷透出凭据 | 载荷**已**由 change `0121` 白名单化（`_PROGRESS_FIELDS`）；前端只**渲染**既有字段，不新增透出面 |
| 前端无 JS 测试基建（不可回归） | 端点层用 pytest 断 **SSE 帧序列**（可回归）；前端以 `npm run build` + 手工冒烟为验收（**如实登记**为已知局限） |
| `POST /task` 被 SPA 静态兜底吞掉 | 路由注册在 `StaticFiles` 挂载**之前**（与既有 11 端点同序，既有「不遮蔽」用例扩一条） |

## 兼容性

- `UIAPILayer.run_task` 的**签名与产出事件逐字不变**（HTTP 面只是加一层适配）。
- 既有 **11 端点**的路径 / 方法 / 响应形状**零变更**（只新增第 12 个）。
- `App.svelte` 右栏新增区块 ⇒ **不改** `SessionList` 的 props / 行为（会话面逐字不动）。
- `lib/api.js` 的 `runStream` / `listSessions` / `fetchMessages` **导出面与行为不变**（`runStream` 改为
  共用私有 SSE 读取实现，语义与产出逐字一致 —— 目的只是避免把同一段 SSE 解析复制第二遍）。
