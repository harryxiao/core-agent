## Why

记忆与 evolution 全量 review 的**批次 C（规模/决策质量）**中，memory 侧有三项确定缺陷：

1. **检索写放大**：`_reinforce` 对每个选中条目调用 `backend.put`，而 `FileBackend.put` 每次都
   **全量重写** JSONL（`_persist` 序列化全部条目 + `os.replace`）。一轮 prompt 读 20 条 ⇒ 20 次
   全量重写，且每轮推理都发生；同时写入侧热字典 `_hot` 只增不减，长进程内存持续增长。
2. **空摘要重复抽取**：摘要器返回空串时只跳过摘要提交，关键事实 / 关系 / 情景归纳**照常执行**；
   原条目因未归档仍是下一轮材料 ⇒ 每轮维护重复调用 3 个抽取器、以同一 `compaction.<sid>`
   trace 重复覆盖写。
3. **失败教训块无独立预算**：注入块至多 5 条，但每条正文上界 2048 字符（且中文更吃 token）——
   最坏约 1 万字符的教训块不占事实预算名额，预算紧张时挤掉事实 / 历史块。

## What Changes

- **memory**：`FileBackend` 新增批量写入口 `put_many`（**单次落盘**）；`_reinforce` 先批量递增
  再批量写回（后端无批量写时逐条回退，语义不变）；写入侧热字典 `_hot` 有界（512 条，写入序淘汰，
  读路径/撤销路径回退冷区）。复用强化仍**逐条**记可撤销效应。
- **memory**：摘要器注入且返回空摘要时 `warnings.warn` 留痕（只报会话键）并**跳过本轮该会话的
  派生抽取**（事实/关系/情景归纳）与摘要提交；未注入摘要器时行为不变。
- **loop**：组合根渲染的「既往失败教训」块**有界**：单条折叠后 ≤500 字符、整块正文 ≤1500 字符
  （条数上界 5 不变）。

## Impact

- 规格：memory「温度分层检索」「记忆压实」MODIFIED；loop「执行循环」MODIFIED。
- 代码：`src/core/memory/backend.py`、`src/core/memory/store.py`、`src/core/runtime.py`。
- 行为：同一检索的强化写回从 N 次全量落盘降为 1 次；`_hot` 超界淘汰（后端仍持有全部条目，读面
  不受影响）；空摘要会话的派生抽取跳过（留痕）；教训块长度有界。均为缺陷/成本修复，缺省无开关。
- 不做：M4 benchmark 记忆隔离与 M8 CJK token 估计（change 0245）；`_truncate` 首条超预算
  （review 判为低风险）；抽取结果的持久去重（M9 采用「本轮跳过」而非条目状态位）。
