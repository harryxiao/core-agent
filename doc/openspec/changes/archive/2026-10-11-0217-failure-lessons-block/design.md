# Design 0217 — 「既往失败教训」注入块

## §1 根因取证（逐字）

| 事实 | 位置 |
|---|---|
| 失败条目**已沉淀**（`tags=["loop","failure"]`、`kind="episodic"`） | `loop/default.py::remember`（`if failed:` 支） |
| 失败摘要构造（任务 ＋ 原因 ＋ 失败轮次 ＋ 失败动作，逐行脱敏、有界） | `loop/default.py::failure_digest:145` |
| 该标签使压实材料**排除**它（只豁免压实，**仍走遗忘** ⇒ 会迁 L4） | `memory/store.py::_PRESERVE_TAGS` |
| `Diagnoser` 消费失败条目、**只进诊断报告** | `loop` 冷路径 / `Diagnoser(failure_lookup=…)`（`0188` / ADR-0179） |
| **无**任何把失败条目回灌推理提示的路径 | 全仓无 `failure` 相关注入块 |
| 通用事实面按**相关性**排序取数（失败条目无优先权） | `DynamicAssembler.build(stage="reason")` |

结论：失败经验**有沉淀、无专属消费面**。

## §2 关键取舍

### §2.1 为什么是**零效应读面**而不是复用 `read()`

`read()` 命中的条目会经 `_reinforce` **+1 `reuse_count`** 并**落盘一个可撤销效应**（`0187` / ADR-0178）。
若教训注入走 `read()`，则**每轮推理**都制造一个写入效应 ⇒ i) 污染 `reuse_count` 排序信号（教训被反复
「使用」而虚高）；ii) 在 `EffectTracker` 里堆积与用户意图无关的效应；iii) 破坏「读取面 SHALL 零效应」的
既有口径（`session_chain` / `summary_for` 同律）。故新开**只读快照**面，走 `_all_entries()`（冷 + 热，层无关）。

### §2.2 为什么**层无关**（不要求 `layer == "L2"`）

失败条目会随遗忘**迁 L4**（`_PRESERVE_TAGS` 只豁免**压实**、不豁免遗忘 —— `0179` 的既有事实）。
若读面要求 L2，则一个「失败经验已积累但被遗忘归档」的会话会**看不见**自己的教训 —— 恰恰是长会话最
需要教训的时刻。故只按 `tags` 过滤、不按层过滤。**风险**：将来若有其它层写入 `failure` 标签，本面会
一并收 —— 缓解：`failure` 标签在本仓**唯一**生产者是 `remember`（`_PRESERVE_TAGS` 亦按它排除），
写侧无第二处。

### §2.3 为什么**新增第 11 个提示词块**而不折入既有块

`ADR-0191`（`0201` 五区块配比）拒的是**重切预算份额**（`plan_blocks` 的 memory/… 五份），
**不是**「块的数量」。本块与之**不冲突**：

- **不改** `plan_blocks` 的任何份额、**不改**任何既有块的字节；
- **独立 opt-in**（缺省关）⇒ 关闭时提示词**逐字不变**；
- 长度**有界**（至多 `_FAILURE_LESSON_LIMIT` = 5 条，每条受既有单条 L2 沉淀条目长度上界约束）；
- 语义**独立**（失败教训 ≠ 相关事实 ≠ 相关笔记 ≠ 分层摘要）⇒ 折入任一既有块都会**改变该块的语义**。

折入「相关事实」的具体害处：事实块按「相关性 + 预算」截断（`build(budget=…)`），教训会被**静默丢弃**；
独立块**无条件在场**（只判空），这正是失败教训要的语义。

### §2.4 为什么**同时**把 `failure` 加入 `exclude_fact_tags`

块启用后，失败条目在「既往失败教训」块与「相关事实」块**双份注入** ⇒ 浪费预算、且两处渲染口径不同
（事实块带 `[source]` 前缀）。同 `0185`（压缩产物）/`0186`（原始步序）的「**专块承载 ⇒ 退出事实面**」
口径。**条件化**是关键：块**未启用** ⇒ `exclude_fact_tags` **逐字**为既有 `frozenset({"steps"})`
⇒ 事实面行为**逐字不变**（这是本 change 的**最高风险点**，必须有锚测试）。

### §2.5 钩子**入参为会话标识**（与 `pinned_notes_consult` 的零参不同）

- `pinned_notes_consult: Callable[[], str]` —— 常驻笔记**与当轮任务无关** ⇒ 零参。
- `notes_consult: Callable[[str], str]` —— 命中笔记**按任务文本**取 ⇒ 一参（任务）。
- 本钩子 `FailureLessonsConsult = Callable[[str], str]` —— 教训**按会话**取 ⇒ 一参（**会话标识**）。
  三个钩子的 arity 各不相同是**语义**决定的，不强行统一。

### §2.6 为什么**不**做因果 / 归因

承 `0202` / ADR-0192 的既有权衡（并以其为**先例**）：仓内无确定性因果事实，模型生成的归因散文
不可测正确性、非可逆、且是**新脱敏面**。本块只做**时序倒序取用**（最近失败的教训排前），
SHALL NOT 推断「这次失败是因为上次」。

## §3 影响面与不可逆性

- **写路径零改动**：不改 `remember` / `failure_digest` / `_PRESERVE_TAGS`。本 change **纯读 + 注入**。
- **可逆性**：注入块与 `exclude_fact_tags` 都是**每轮重算**的派生态，无持久化 ⇒ 配置回退即恢复。
- **红线**：`exclude_source_prefixes=("beast.","pet")` **逐字不动**；宠物 / 子 / 神兽 loop **不接**该钩子。
- **脱敏**：教训正文**已在写入时**逐行脱敏（`0179` over-redact）⇒ 读面**无需**二次脱敏（本 change
  SHALL NOT 引入新的脱敏判据）。留痕只报 `error` 字符串（不含条目正文）。

## §4 未决 / 局限（登记）

1. **教训与事实面的内容重叠**：块启用后失败条目退出事实面，但**语义事实**（如从失败中抽出的 keyfact）
   仍可能在事实面 —— 二者是**不同条目**，不构成重复。
2. **只按会话取**：跨会话的同类失败**不**互相可见（会话维度是刻意的隔离口径）。
3. **非因果**：本块只提供时序倒序的**原文回顾**，模型是否从中借鉴由模型自决（不可测）。
