# Design

## Context

全局架构审查（2026-09-22）发现：中优先级八模块在断线 / 超时 / 缓冲溢出 / 失败 / 挂起 / 资源超限等异常场景下缺少异常处理与连接管理语义。本 change 补齐这些语义。

## Decisions

- **ui SSE 断线重连**：SSE 流式连接断开后客户端按指数退避自动重连并心跳探测连接存活，避免流式输出卡死
- **deployment 客户端断线与会话清理**：检测客户端断开（含心跳 / 超时判定），回收该客户端会话与连接资源，不影响其他并发客户端
- **observability 遥测缓冲与导出重试**：内存缓冲设上限 + 溢出兜底（落盘或按优先级丢弃低价值事件），导出失败按指数退避重试 + 背压，不阻塞主循环
- **rag 摄取/重建失败降级**：embedding 失败 / 索引损坏 / 重建失败时降级不阻断检索，保留旧索引（或纯 LLM 生成）兜底
- **memory 检索失败降级 + 并发压实一致性**：检索失败降级，压实过程保证并发一致性避免读写冲突
- **orchestration 断点续跑 + fan-out 幂等**：长任务支持挂起 / 恢复 / 取消；并行扇出按幂等派发避免重复执行
- **im 消息幂等 + 重连退避**：重复消息幂等处理避免重复消费；断线重连按指数退避
- **skills 超时与资源上限**：技能执行超时 / 资源超限时中断并回收资源，不阻塞主循环
- **spec 扩展非新 cap**：八模块均归属既有 capability，不新建 capability

## Risks / Trade-offs

- 指数退避参数（初始间隔 / 最大次数 / 退避因子）留待编码阶段确定
- 旧索引兜底依赖索引版本管理，需保证降级期间检索可用性
- 幂等去重依赖消息 / 任务稳定 ID，与既有消息与任务标识约定保持一致

## Open Questions

- 遥测背压降采样 / 暂停非关键采集的具体策略粒度留待实现阶段确定
- 断点续跑的持久化介质与恢复时机留待编码阶段确定
