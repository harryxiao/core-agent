# Design

## Context
CORE-Harness 采用"插件即原子、记忆即光谱、进化即结晶"的结晶经济闭环。本变更落地六主轴能力，是后续横切能力（权限、约束、遥测、上下文）的宿主骨架。

## Decisions
- **Loop 作为唯一主轴**：所有能力通过横切中间件插入，而非各自独立线程，保证执行顺序可预测、可追踪。
- **Memory 采用光谱分层而非扁平 KV**：L0–L4 层间用轻量索引连通，热数据常驻、冷数据按需，对抗上下文稀缺。
- **Tool 用 coeffect 声明副作用**：把"能做什么"与"允许做什么"解耦，为权限引擎提供校验依据。
- **MCP 作为外部能力统一入口**：本地工具与外部 MCP 工具同构映射，错误隔离不拖垮主循环。
- **Evolution 只进化技能/SOP，不改代码**：避免自改源码的风险，结晶产物需人工评审入库。

## Risks / Trade-offs
- **中间件顺序敏感**：横切中间件顺序影响语义，需在注册时显式排序并文档化。
- **分层记忆检索延迟**：冷数据按需加载可能引入延迟，用预算裁剪对冲。
- **进化质量**：经验采集噪音可能导致劣质技能候选，靠评审队列 + A/B 兜底。

## Open Questions
- L1 索引的存储引擎选型（KV vs 全文检索）。
- 结晶产物的评审是纯人工还是"人工 + 指标预筛"。
